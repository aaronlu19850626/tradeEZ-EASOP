## 2. 系统定位与模块

这是以人工点击下单为入口、由 EA 执行持仓管理的半自动交易面板，不是根据指标自动产生多空信号的策略系统。

| 模块 | 输入与职责 | 关键边界 |
|---|---|---|
| 订单执行 | 市价、指定价格限价、快捷偏移挂单 | 买卖信号由用户决定，手数固定输入 |
| 剥头皮管理 | 初始 SL/TP、峰值追踪、可选超时平仓 | 魔术号识别；标准点固定 0.01 |
| 趋势管理 | 分段保本、锁盈、减仓、追踪 | 部分平仓依赖账户模式与服务器支持 |
| 普通风控 | 策略亏损限额、总亏损限额、连亏冷却 | 主要阻止新增开仓，不等于全部持仓强平 |
| 利润保护 | 记录净盈利高点，回撤达到条件发起全平 | 高点包含浮盈；清盘只发一次异步请求组 |
| 统计 | 日/周收益、胜负、历史、日报 | 部分按当前品种，部分按账户；并非统一口径 |
| 数据同步 | 品种、成交、快照、配置、心跳 | WebRequest 同步阻塞当前 EA 事件处理 |
| 界面 | 完整/精简面板、弹窗、更新日志、官网、遮罩 | 遮罩是反馈与交互限制，不会解除线程阻塞 |
| 状态持久化 | 终端全局变量、跟踪数组文件 | 多处仅按账号区分，多图表实例存在冲突风险 |

## 3. 事件执行与数据路径

| 入口 | 当前主要顺序 | 影响 |
|---|---|---|
| OnInit，约 4128 行 | 加载状态、重建基础统计、风控、画面、启动定时器 | 初始化本身不直接执行完整网络同步 |
| OnTick，约 4200 行 | 逐持仓动态管理 → 风控 | 本地止盈追踪、减仓等依赖 EA 能及时执行 |
| OnTimer，约 4234 行 | 风控/画面 → 每日同步判断 → 常规定时同步 | 一次请求或完整同步批次占用当前处理流程 |
| OnTradeTransaction，约 4314 行 | 成交事件触发统计/风控/刷新 | 未形成异步平仓请求的完整成功/失败核销机制 |
| OnChartEvent | 按钮与弹窗操作、输入框、语言、最小化等 | 网络请求或模态确认期间不能正常立即处理 |
| OnDeinit | 停止定时器、清理本 EA 图形对象等 | 不应将卸载 EA 视为自动平仓操作 |

MT5 将事件按队列处理；OnTick 正在执行或已有 NewTick 排队时，新 tick 不会无限逐个补入。因此阻塞不仅是“画面晚一点更新”，还可能跳过中间行情状态。服务器已经接受的 SL/TP 与 EA 本地动态计算必须区分：前者由服务器执行，后者需要 EA 运行。[MQL5 OnTick](https://www.mql5.com/en/docs/event_handlers/ontick)、[WebRequest](https://www.mql5.com/en/docs/network/webrequest)。

### 同步的三种入口

1. 常规定时：全账户 PositionsTotal() 为零，且没有编辑价格、距用户操作至少约 5 秒，才执行到期任务。
2. 手动同步：显示风险确认；用户确认后允许有持仓同步。
3. 每日同步：按北京时间重置日判断，首次挂载可能补做；允许有持仓同步，正在编辑价格时延后。

“空仓”检查不等于没有挂单，也无法保证请求期间不会发生挂单成交。每日标记在发起请求前写入：失败后不会因每日标记再次执行同一日的完整初始化同步。常规其他任务仍可能随后运行。

## 4. 高优先级发现

以下“已确认”指源码存在该分支或缺少相应处理，不代表已测量出实际账户损失。验证应使用隔离模拟环境。

### A. 网络和确认框阻塞本地交易管理（设计限制）

证据：SyncWebRequest（约 3436 行）、RunFullDataSync（约 4211 行）直接调用同步网络请求；手动确认使用模态 MessageBox。

影响：动态改 SL、EA 主动平仓、趋势减仓、按钮事件均可能延后。一个批次包含多个请求，单请求超时不等于完整同步耗时上限。

现有缓解：常规定时仅空仓执行，界面显示同步状态和遮罩。仍有风险：手动/每日同步例外，以及挂单在同步期间成交。

后续建议：若要求持仓管理不受网络影响，应将网络同步隔离到独立执行程序或独立 EA 通信流程；当前遮罩不是线程隔离方案。

### B. 剥头皮追踪在回落到触发线以下时跳过判断

证据：ManageScalpTrailingStop（约 1001 行）先判断当前浮盈是否低于触发阈值，再处理已存在的峰值跟踪。

影响：已经激活追踪的订单若快速跌回触发线下，本次 tick 不执行本地峰值回撤出场分支。之前已成功设置的服务器 SL 可能起保护作用，但不能等同于本地逻辑正确。

验证：先达到触发线并形成峰值，然后用跳价直接跌到触发线下；比较本地平仓与服务器 SL 行为。

后续建议：激活状态应持久保持；触发门槛只控制首次激活，不应阻止已激活订单继续检查。

### C. 趋势追踪与减仓存在分支跳过

证据：ManageTrendTrailingStop（约 1108 行）进入追踪阈值分支后提前返回；减仓位于后续阶梯分支。

影响：价格直接从低档跳至追踪阈值以上，可能跳过预期减仓；已进入追踪后若跌回阈值以下，又走阶梯逻辑，不再按该分支检查历史峰值出场。

验证：分别测试 790 → 1010 标准点、1050 → 650 标准点，以及多空两方向。

后续建议：减仓状态与追踪激活状态独立管理，退出触发应与当前是否仍高于激活线解耦。

### D. 批量平仓只有提交，没有完整成交确认及补偿

证据：ClosePositionsAsync（约 1707 行）、CloseAll（约 1754 行）、EnforceMoatLiquidation（约 1781 行）。保护清盘发出请求后即设置已清盘标志。

影响：服务器拒单、部分成交、交易断线或竞态可能留下持仓；护城河不会自动持续重试剩余仓位。提示“已完成”不应作为仓位确实清零的证据。

官方明确：OrderSendAsync 返回成功不保证请求已被服务器接受或实际成交。[OrderSendAsync](https://www.mql5.com/en/docs/trading/ordersendasync)。

后续建议：按请求/票据跟踪结果，回查剩余量，采用有界重试和失败告警；避免重复平仓导致误开反向仓位。

### E. “改趋势”并未切换到趋势管理

证据：ConvertScalpToTrend（约 952 行）清 TP、保留 SL、登记 promoted 状态，但没有改变策略魔术号；ManageAllTrailingStops（约 1192 行）仍按原分类分派。

影响：用户可能认为已启用趋势阶梯保本/减仓，实际仍由剥头皮规则管理，统计、平剥头皮范围也继续按原魔术号归属。

后续建议：明确产品语义。若需要真实迁移，应独立维护管理模式及持久化，不依赖不可随意修改的持仓魔术号。

### F. 盈利阈值名称与动作不一致，默认比例需复核

证据：CheckProfitProtection（约 1417 行）。ProfitLiquidation 和 ProfitShutdown 达到后主要锁定开仓；实际全平由回撤条件触发。第一档回撤默认比例为 300.0，并除以 100 计算。

影响：默认第一档是回撤高点的 300%，不是 30%；“清盘触发”参数名可能令用户误以为盈利达到 1000 就立即平仓。

后续建议：先确认预期规则与参数，再调整命名/默认值/执行逻辑；本次手册按实际代码解释，未擅自改值。

## 5. 其他重要发现

| 项目 | 证据/位置 | 实际影响与建议 |
|---|---|---|
| 挂单不占仓位上限 | CountPositions、ValidateOpen，约 526/1661 行 | 可挂多单后同时成交，超过策略上限；建议预留挂单占用 |
| 风控锁定不等于撤挂单 | 普通限额与连亏分支 | 既有挂单仍可能成交；应明确风控触发时的挂单政策 |
| “全局”实际当前品种 | AllFloatingPL/AllRealizedPL/CloseAll | 不能当成全账户风控；全平还可能覆盖当前品种手动单/其他 EA 单 |
| 多实例持久化冲突 | PVKey，约 3245 行；跟踪文件按登录账号命名 | 同账号不同品种/实例可能覆盖状态；建议实例级命名空间 |
| 日报跨日区间 | CheckDayRollover → ExportDailyReport，约 1377/1288 行 | 导出函数重新计算新交易日起点，可能未导出刚结束的一天；需显式传旧区间 |
| 连亏以秒去重 | UpdateConsecutiveLoss，约 1460 行 | 后续同秒到达的平仓可能被 dtime <= LastDealTime 跳过；应按成交 ticket/毫秒核销 |
| 减仓适配账户模式 | PositionClosePartial 调用 | 当前设计适合对冲持仓；净额账户不能直接假定兼容 |
| CTrade 布尔值被当作成功 | 修改 SL、清 TP、部分平仓等 | 应检查 ResultRetcode 和持仓最终状态，而不只看 bool |
| 手数小数位固定 | NormalizeLots，约 353 行 | 非常规步长/精度品种可能产生不正确归一化；按 volume step 确定精度 |
| 同步开仓时间可能错误 | CollectDealsAfterCloseTime，约 3580 行 | 先在窄历史窗求开仓时间，再扩至 30 天且未重新计算；存在开仓时刻误报 |
| 历史同步窗口限制 | 同上及 SyncDeals，约 3763 行 | 7 天回退、30 天扩展无法保证长期持仓完整开仓信息；部分平仓也会被上传 |
| 日内交易分类不完整 | DealStrategyType，约 397 行 | 若原始开仓不在当前历史选择范围且平仓信息不足，策略识别可能偏差 |
| 手续费统计边界 | RealizedPL/ComputeDailyStats | 只累计平仓成交佣金，开仓手续费可能漏计；不等同完整账户净收益 |
| 统计笔数不等于订单数 | ComputeDailyStats，约 664 行 | 部分平仓按多笔成交计胜负；卡片与统计弹窗零值容差不同 |
| 隐藏/未接入参数 | WeeklyHint、ConsecutiveSLWarning、AlignIntervalHours | 周计划不会自动调风险，未见连续止损提醒/哈希校准对应任务生效 |
| 本地性能 | 历史扫描、日志、保存、UI 刷新调用链 | 即使网络关闭仍可能有开销；需计时剖析后优化，不能认定所有卡顿仅由刷新导致 |
| 遮罩作用域 | ShowSyncOverlay，约 3387 行 | 覆盖主面板而非整个终端；侧窗或已排队事件仍需单独验证 |
| 鼠标手型 | 当前鼠标移动处理 | 自定义切换逻辑未接入当前移动分支，不应将“稳定手型”列为已交付功能 |

部分平仓接口适用范围与结果检查见 [CTrade PositionClosePartial](https://www.mql5.com/en/docs/standardlibrary/tradeclasses/ctrade/ctradepositionclosepartial)。

## 6. 建议验收矩阵

先备份源码、输入参数和日志，使用专用模拟账户；避免与其他 EA 共用相同魔术号。网络同步测试需终端模拟环境，策略测试器不支持 WebRequest。

| 测试组 | 操作 | 检查点 |
|---|---|---|
| 市价买卖 | 各开一单 | 魔术号、手数、SL/TP 距离、拒单提示 |
| 限价/快捷价 | 两方向各挂单，触发成交 | 价格单位、最小距离、挂单数量与持仓上限 |
| 剥头皮追踪 | 达到阈值、创新高、普通回撤、跳跌 | 每阶段 SL 与本地主动平仓，阈值下回落 |
| 趋势阶梯 | 依次到 300/500/800/1000，再跳越档位 | 保本、锁盈、减仓次数、尾随激活持久性 |
| 改趋势/撤 TP | 有/无合格持仓各操作 | 修改实际范围，风控禁用和重置恢复样式 |
| 批量平仓 | 混合策略、手动单、其他品种、挂单 | 严格确认作用域，拒单后剩余仓位及告警 |
| 普通熔断 | 策略限额、总限额、连续亏损 | 开仓被阻止但持仓仍管理，挂单行为明确 |
| 利润保护 | 达高点后回撤，模拟平仓失败 | 锁定与清盘分别触发，残仓是否被识别 |
| 常规同步 | 空仓/有仓/仅挂单；操作后不足 5 秒 | 有仓不自动常规同步，挂单成交竞态记录 |
| 手动同步 | 取消/确认、持仓时确认 | 不确认不请求；准确警示；遮罩与文字 |
| 每日同步 | 跨 04:50、首次挂载、失败重启 | 有仓例外、每日期限、失败是否补做 |
| 同步异常 | 超时、错误密钥、服务器拒绝、多批成交 | 遮罩必清除、错误可辨认、交易无误触 |
| 界面 | 最小化/还原、缩放、侧窗、同步期间点击 | 覆盖尺寸、文字可见、旧点击是否滞后执行 |
| 状态恢复 | 重启终端、换图、两个实例并行 | 高点、冷却、跟踪数组及状态互相污染 |
| 日报统计 | 跨日有仓、部分平仓、开仓佣金、长持仓 | 与终端真实成交账单逐笔对账 |
| 官网/更新日志 | 标题/版本点击，官网点击 | DLL 禁用提示、安全外链、最近 10 版展示 |

## 7. 维护优先顺序

1. 先明确真实交易范围、账户模式及利润保护规则；将手册风险告知实际操作者。
2. 优先修正追踪激活状态、异步平仓核销和残仓处理，再做网络线程隔离。
3. 统一状态命名空间、历史区间与成交标识，修正统计/同步一致性。
4. 最后做性能计时与 UI 体验优化，避免以遮罩或降低刷新频率代替交易正确性修复。

上述是后续建议，不表示本次已经实施。EA 的实际成交、滑点、止损执行仍受行情、连接与交易服务器条件影响；本分析不作收益或无风险保证。
