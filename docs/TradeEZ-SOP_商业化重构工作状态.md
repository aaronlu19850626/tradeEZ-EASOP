## 3. 不可突破的技术边界

1. MT5 客户端和 EA 完全停止后，EA 无法继续接收 Tick、计算新峰值、移动止损、主动平仓或减仓。
2. 离线期间只能依赖交易服务器已经确认的 SL、TP 和挂单；本地动态追踪不是服务器功能。
3. 重启后可以重建成交统计，但无法从当前价格精确还原关机期间经历过的真实 Tick 峰值路径。
4. 本轮目标是实现“服务器固定保护兜底、在线动态保护、重启可靠恢复、异常明确告警”，不承诺终端关闭后动态策略继续运行。

## 6. 固定验收流程

每个工作项统一执行：

1. 说明设计、影响范围和不可避免的取舍。
2. 项目所有者确认设计后再修改交易逻辑。
3. 修改 `.mq5` 时同步更新文件头部北京时间。
4. 编译必须达到 0 errors、0 warnings。
5. 执行该项专项测试。
6. 执行关联功能回归测试。
7. 在本文件记录修改文件、更新日志、测试证据、失败项和剩余风险。
8. 向项目所有者提交变更摘要、源码差异、编译结果和测试证据。
9. 只有在项目所有者明确确认后，才执行 Git 提交和 GitHub 推送。
10. Git 暂存前必须确认暂存区只有 `tradeEZ.mq5`；不得提交文档、图片、编译产物或其他工作区文件。
11. 推送完成后记录提交 SHA、分支和推送结果，再将工作项状态改为“已完成”。

### 6.1 GitHub 提交规则

- 远程仓库：`origin` → `https://github.com/aaronlu19850626/tradeEZ-EASOP.git`。
- 当前分支：`main`。除非项目所有者另行指定，后续确认后的源码更新提交到该分支。
- 每次只允许暂存和提交 `tradeEZ.mq5`，使用显式文件路径，不使用 `git add .` 或 `git add -A`。
- 提交前检查 `git diff --cached --name-only`，结果必须只有 `tradeEZ.mq5`。
- Git 提交信息应包含工作项编号和简明更新内容，作为 GitHub 可追溯更新日志。
- 本地工作状态文件持续记录详细变更；它暂不提交到 GitHub。
- 面板中的公开版本更新日志只在形成用户版本时更新，不把每次内部开发提交都伪装成公开发行版本。
- 当前 `tradeEZ.mq5` 在本轮开发开始前已经存在未提交修改；首次提交前必须向项目所有者展示相对仓库基线的完整差异，确认后才能整体提交。
