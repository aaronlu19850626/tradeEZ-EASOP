# TradeEZ-SOP 第 3 项：逐票状态持久化设计

> 状态：P3-D01 至 P3-D08 已全部确认，代码完成并等待专项运行验证  
> 日期：2026-09-19（北京时间）  
> 本阶段只冻结状态模型、命名空间、迁移和验收规则；确认后再修改交易代码。

## 1. 目标

让每一张仍在持仓中的交易票据在切换周期、EA 重载、MT5 重启和跨日后，继续保持原来的管理阶段，不因为每日统计初始化而清空，也不与同账户的其他品种或其他 EA 实例互相覆盖。

第 3 项只解决“已经记录的状态可靠保存和恢复”。终端关闭期间的状态推断、缺失状态接管和跨日补做属于第 4 项。

## 2. 当前实现与问题

当前文件：

```text
MQL5/Files/GSOP_state_<account>.csv
```

当前保存四类数组：

| 标签 | 状态 |
|---|---|
| TOC | 用户取消剥头皮超时强平 |
| PRO | 剥头皮持仓已执行“改趋势” |
| TRK | 趋势单是否已减仓、趋势追踪峰值 |
| SCT | 剥头皮追踪峰值 |

已确认问题：

1. 文件首行绑定 `g_DayStart`，跨日后整份逐票状态拒绝恢复。
2. 文件名只有账号，同账户不同品种、不同图表实例会覆盖同一文件。
3. 文件没有 schema 版本、服务器、品种、实例 ID 或保存时间，无法可靠迁移和审计。
4. 文件直接覆盖写入，中断时可能留下半份文件。
5. 只保存 ticket，没有 position identifier、magic、开仓时间等身份校验信息，票号误匹配时缺少防护。
6. 部分状态依靠脏标记延迟到当前 Tick 末尾落盘，异常终止前可能来不及保存。
7. `OnDeinit()` 没有执行最终状态检查点。
8. 账户级全局变量只按账号命名，同样存在跨服务器、品种和实例冲突。

## 3. 新命名空间

### 3.1 稳定实例 ID

新增用户参数：

```text
Inp_InstanceId = "primary"
```

实例 ID 用于状态命名空间，不使用 `ChartID()`，因为图表重建后 ChartID 可能变化。建议允许英文字母、数字、短横线和下划线，其他字符规范化为下划线。

用户在同一账户、同一品种运行多个主 EA 时，必须给每个实例设置不同的 `Inp_InstanceId`。检测到同命名空间已有活跃实例时，后启动实例进入只读告警状态，不写状态文件、不执行持仓管理。

### 3.2 命名空间组成

状态身份至少包含：

```text
schema_version + broker_server_hash + account_login + symbol + instance_id
```

建议文件：

```text
MQL5/Files/TradeEZ/state/v2/
  <server_hash>_<account>_<symbol>_<instance_id>.csv
```

每日统计全局变量也使用相同命名空间，但逐票文件不再包含“必须等于今日”的恢复条件。

## 4. 逐票记录模型

每个当前或最近管理过的持仓保存一条版本化记录：

| 字段 | 类型 | 说明 |
|---|---|---|
| ticket | uint64 | 当前持仓 ticket |
| position_id | uint64 | MT5 position identifier，用于二次校验 |
| symbol | string | 实际经纪商品种名 |
| magic | int64 | 原始策略 magic |
| open_time_msc | int64 | 开仓毫秒时间，用于防止错误匹配 |
| management_mode | enum | SCALP、TREND 或 PROMOTED |
| timeout_cancelled | bool | 用户是否取消该票超时强平 |
| scalp_track_active | bool | 是否已经进入剥头皮峰值追踪 |
| scalp_peak_points | double | 剥头皮浮盈峰值 |
| trend_reduced | bool | 趋势第三档减仓是否已经执行 |
| trend_peak_points | double | 趋势追踪浮盈峰值 |
| last_volume | double | 最近已知剩余手数，供恢复审计 |
| updated_utc | int64 | 最近保存 UTC 秒 |

逐票状态生命周期独立于统计日。每日重置只能清理日统计与当日风控状态，不得清空上述逐票字段。

## 5. 保存规则

以下动作发生后立即保存，不等待下一轮面板刷新：

- 新票首次进入管理；
- 取消超时强平；
- 执行“改趋势”；
- 剥头皮或趋势峰值提高；
- 趋势减仓状态改变；
- 持仓消失或剩余手数变化；
- EA 正常卸载。

同时每 30 秒做一次检查点，弥补未捕获的异常路径。

保存采用：

```text
写入 .tmp → FileFlush → FileClose → FileMove(FILE_REWRITE)
```

正式文件始终保持上一份完整版本或新完整版本，不直接截断覆盖。

## 6. 恢复与校验规则

启动恢复时按以下顺序校验：

1. schema 版本可识别；
2. 服务器、账号、品种、实例 ID 与当前实例一致；
3. ticket 当前仍存在；
4. position identifier、symbol、magic、开仓时间与当前持仓一致；
5. 数值字段在合法范围内，峰值不得为 NaN 或负无穷；
6. 校验通过才恢复对应逐票状态。

不匹配记录不直接套用到持仓。记录先保留为审计数据并输出一次明确日志，由第 4 项决定缺失状态如何保守重建。

## 7. 已关闭记录和文件清理

- 持仓确认消失后，将记录标为关闭，不再参与管理。
- 为避免交易事务瞬态或短暂查询失败导致误删，关闭记录保留 7 天后再压缩清理。
- 同一 position 的部分减仓只更新 `last_volume`，不得删除状态或重置 `trend_reduced`、峰值。
- 文件损坏时保留原文件并以错误日志告警，不静默覆盖为一份空状态。

## 8. 旧版迁移

新版文件不存在时，可以只读尝试旧文件：

```text
GSOP_state_<account>.csv
```

迁移限制：

1. 仅迁移当前仍存在并且 symbol 等于当前图表的 ticket。
2. 旧文件没有服务器、品种和实例信息；检测到同账户多实例或归属不明确时禁止自动迁移。
3. 成功迁移后立即写新版文件，旧文件保留，不删除、不覆盖。
4. 旧文件的 DAY 只作为来源元数据，不再阻止仍在持仓的票据迁移。
5. 每个新命名空间只执行一次迁移并记录 migration 标志。

## 9. 多实例边界

命名空间只能防止状态文件互相覆盖，不能自动判断两个实例是否正在管理同一张持仓。当前订单没有写入稳定 instance ID，因此第 3 项采用以下安全边界：

- 同一账户、同一 symbol、相同策略 magic 组合只允许一个活动主 EA；
- 不同品种可以使用相同 magic，但状态文件按 symbol 隔离；
- 若未来允许同品种多个交易实例，必须使用不同 magic 或把 instance ID 写入可恢复的订单身份，再单独升级归属协议。

## 10. 验收场景

| ID | 场景 | 通过条件 |
|---|---|---|
| P3-01 | 有峰值追踪持仓时切换周期 | 峰值和追踪阶段不变 |
| P3-02 | 有持仓时移除并重新挂载 EA | 逐票状态完整恢复 |
| P3-03 | MT5 正常关闭后重启 | 逐票状态完整恢复 |
| P3-04 | 持仓跨越每日初始化 | 日统计重置，逐票状态不重置 |
| P3-05 | 趋势单已减仓后重启 | 不重复执行第三档减仓 |
| P3-06 | 点击改趋势后重启 | 管理模式标记仍保留 |
| P3-07 | 取消超时强平后重启 | 该票不重新出现超时强平 |
| P3-08 | 部分减仓后保存 | 状态保留，只更新剩余手数 |
| P3-09 | 同账户两个不同品种 | 状态文件互不覆盖 |
| P3-10 | 相同命名空间启动第二实例 | 第二实例告警且不管理持仓、不写文件 |
| P3-11 | 保存过程中模拟中断 | 正式文件仍是完整旧版或完整新版 |
| P3-12 | 文件中 ticket 与 position_id 不匹配 | 拒绝恢复并记录原因 |
| P3-13 | 旧版文件迁移 | 符合条件的当前持仓状态迁入 v2，旧文件保留 |
| P3-14 | 持仓关闭后立即出现新交易 | 旧状态不会套用到新票 |
| P3-15 | 编译和关联回归 | 0 errors、0 warnings；下单、追踪、减仓和重置无回归 |
