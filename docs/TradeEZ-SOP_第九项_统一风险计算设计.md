# TradeEZ-SOP 第九项：统一风险计算设计

> 状态：P9-D01 至 P9-D13 已确认；主程序已完成首轮开发和编译，等待模拟账户专项验证  
> 范围：当前品种持仓、活动挂单、待确认新增风险请求、容量、止损风险、保证金、报价质量和熔断后的挂单处理

## 1. 本项目标

当前系统的回撤熔断继续负责回答“今天已经亏了多少”；新增统一风险快照负责回答“如果所有已承诺风险都在服务器止损处退出，今天最多可能亏到哪里”。两者同时生效，任何一个不允许新增风险时，市价开仓和新挂单都必须拒绝。

统一风险计算不承诺消除跳空、流动性枯竭和服务器滑点。它是基于服务器已确认 SL 和可配置缓冲的保守估算，不是保证成交价。

## 2. 现状审计

| 编号 | 当前行为 | 风险 |
|---|---|---|
| P9-01 | `CountPositions()` 只统计已成交持仓 | 可以连续建立多张挂单，触发后突破策略最大仓位 |
| P9-02 | 分项和总熔断只使用已实现盈亏与当前浮盈 | 没有反映持仓未来到 SL 的损失 |

| P9-12 | “全局”文字实际只覆盖当前图表品种 | 商业用户可能误认为覆盖整个账户 |

## 3. 两条风险防线

### 3.1 已发生盈亏熔断

保留现有实时熔断语义：

- 剥头皮净盈亏达到剥头皮额度，只禁止剥头皮新增风险；
- 趋势净盈亏达到趋势额度，只禁止趋势新增风险；
- 当前品种总日净盈亏达到总额度，禁止两个策略新增风险；
- 只有总日回撤触发时读取“是否强平”开关；分项熔断永不强平。

### 3.2 预计止损风险预算

对当前品种生成不可变风险快照：

1. 统计当前服务器持仓；
2. 统计当前服务器活动挂单；
3. 统计账本中尚未在服务器对象中体现的新增风险请求；
4. 去重已经物化为持仓或挂单的请求；
5. 对准备提交的新订单做一次“加入候选订单后的快照”；
6. 同时检查策略预算、当前品种总预算、容量和保证金。

退出、减仓、撤单和收紧 SL 请求在服务器确认前不释放风险预算。

## 4. 预计止损风险计算

### 4.1 统一公式

```text
预计日净盈亏 = 当日已实现现金盈亏
             + Σ 当前持仓在服务器 SL 价格的预计盈亏
             + Σ 活动挂单从预计成交价到 SL 的预计盈亏
             + Σ 未物化新增请求从请求价到 SL 的预计盈亏
             - 风险缓冲

预计止损风险占用 = max(0, -预计日净盈亏)
```

策略预算分别按策略 Magic 聚合。当前品种总预算包含本品种的手工单和其他 EA 订单。账户余额、净值和保证金仍明确标注为账户级。

### 4.2 计算方法

- 金额统一使用账户入金币种；优先调用 `OrderCalcProfit()`，不手写黄金专用金额公式。
- 持仓使用实际开仓价、实际剩余手数和服务器当前 SL。
- 挂单使用服务器挂单价、挂单手数和服务器 SL。
- 待确认请求使用账本中的方向、请求价、手数和目标 SL；账本升级后必须持久化这些字段。
- 止损方向错误、SL 为零、报价无效或 `OrderCalcProfit()` 失败，风险状态记为 `UNKNOWN`，按失败关闭原则禁止新增风险。
- 负向止损损失乘以风险缓冲；锁定盈利的 SL 不因缓冲变成亏损。

MetaQuotes 官方说明：`OrderCalcProfit()` 按当前账户环境返回账户币种的预估损益，但实际结果可能随市场环境变化；因此仍需额外缓冲。保证金预估使用 `OrderCalcMargin()`，账户现状读取 `ACCOUNT_MARGIN_FREE` 和 `ACCOUNT_MARGIN_LEVEL`。

## 5. 去重与状态边界

- 服务器持仓或挂单是第一事实来源。
- 账本新增请求只有在尚未找到对应服务器持仓、活动订单或历史订单/成交时才额外占用风险。
- `SUBMITTED`、`ACCEPTED`、`PARTIAL`、`AMBIGUOUS` 均占用风险。
- `CONFIRMED` 且服务器对象已纳入快照后，不再作为请求重复计算。
- `FAILED`、`CANCELLED` 不占用风险。
- 平仓已提交但服务器持仓仍存在时，继续按完整实际手数计入；不得提前释放。
- 部分平仓只按服务器当前剩余手数计算；目标余量尚未确认前不按目标手数乐观计算。

## 6. 容量规则

```text
策略已占容量 = 策略持仓数
             + 策略活动挂单数
             + 尚未物化的策略新增风险请求数
```

- 每张独立挂单占一个仓位名额；不假设多张挂单互斥。
- 候选订单加入后超过 `Inp_ScalpMaxPositions` 或 `Inp_TrendMaxPositions` 时拒绝。
- 已经超出容量的外部状态不自动平仓或撤单，但在恢复到范围内前禁止该策略新增风险。
- 若用户需要同时布置多张候选挂单，应显式提高该策略最大仓位参数，而不是绕过容量统计。

## 7. 熔断后的挂单策略

- 剥头皮分项熔断：自动撤销本实例剥头皮挂单，不平持仓，不影响趋势挂单。
- 趋势分项熔断：自动撤销本实例趋势挂单，不平持仓，不影响剥头皮挂单。
- 连亏冷却：自动撤销本实例两个策略的挂单，不平持仓。
- 当前品种总日回撤熔断：无论强平开关是否开启，先撤销本实例两个策略的挂单；开关关闭时保留持仓继续受保护，开启时持续清理当前品种全部持仓和全部挂单。
- 仅因“预计止损风险预算已满”而禁开时，不自动撤销已计入预算且保护完整的挂单。
- 手工单及其他 EA 挂单只计入当前品种总风险；普通分项熔断不替用户修改。只有总日回撤强平开关开启或护城河清盘时才按既有规则清理当前品种全部订单。

## 8. 报价和保证金门槛

建议新增参数：

| 参数 | 推荐默认值 | 作用 |
|---|---:|---|
| `Inp_RiskBufferPercent` | `10.0` | 对预计负向止损损失增加 10% 缓冲 |
| `Inp_MaxEntrySpreadPoints` | `80` | 最大允许点差，单位为 MT5 平台 Point |
| `Inp_MaxQuoteAgeSeconds` | `5` | 最新 Tick 超过该秒数时禁止新增风险 |
| `Inp_MinProjectedMarginLevel` | `200.0` | 加入候选订单后的保守预计保证金水平下限 |
| `Inp_CloseOnDailyDrawdown` | `false` | 总日回撤熔断时是否强平当前品种 |

保证金检查：使用 `OrderCalcMargin()` 估算候选订单保证金，与当前账户保证金合并计算保守预计保证金水平。函数失败、自由保证金不足或预计水平低于下限时拒绝。该估算不试图替代交易服务器的最终保证金审核。

报价检查：必须成功取得 `MqlTick`；Bid/Ask 为正、Ask 不小于 Bid；Tick 时间未超限；点差不超过参数。市价单、指定限价单和快捷挂单统一执行，不留旁路。

## 11. 失败策略

- 风险快照任一关键对象计算失败：禁止新增风险，已有持仓继续管理。
- 手工或外部订单没有有效 SL：当前品种风险为未知，禁止 TradeEZ 新增风险，但不自动修改外部订单。
- 报价过期或断流：禁止新增风险，不影响平仓、撤单、减仓和收紧保护。
- 账本中存在无法核实的新增风险：按其完整请求风险计入；缺少方向或价格时风险未知并禁开。
- 风控计算不得使用未来目标 SL 代替服务器尚未确认的当前 SL。
