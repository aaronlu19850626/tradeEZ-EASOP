# TradeEZ-SOP 第 2 项测试说明：独立数据同步 EA

> 版本：线程隔离兼容版  
> 日期：2026-09-18（北京时间）

## 1. 本次验收目标

验证数据同步的网络阻塞只发生在 `tradeEZSync.mq5`，不会再阻塞 `tradeEZ.mq5` 的 Tick、Timer、按钮和动态风控。

## 2. 部署方式

1. 在交易品种图表挂载 `tradeEZ.ex5`。
2. 另开任意一个图表，挂载 `tradeEZSync.ex5`；同一交易账户只挂一个同步 EA。
3. 在同步 EA 参数中配置 `Inp_ApiBaseURL`、`Inp_SecretKey` 和同步周期。
4. 将 API 域名加入 MT5“工具 → 选项 → EA交易 → 允许 WebRequest 的 URL 列表”。
5. 主 EA 参数页和主面板不应再出现任何同步参数、同步状态或“同步数据”按钮。

## 3. 必测场景

修复版本测试前必须按顺序重新加载：

1. 先移除并重新挂载主 EA，等待其生成新版分类实例清单。
2. 再移除并重新挂载同步 EA，保留原 API 地址和密钥参数。
3. 点击一次“同步数据”，再点击“确认同步”。
4. 专家日志中 `Sync Settings` 应返回 HTTP 2xx；如果仍失败，日志现在会输出服务器响应正文，可直接用于定位后端字段校验。

| ID | 操作 | 预期结果 |
|---|---|---|
| T2-01 | 只挂主 EA | 报价、下单、平仓和动态风控正常；主面板无同步控件 |
| T2-02 | 挂载同步 EA，配置正确密钥 | 同步面板先显示正在同步，完成后显示同步空闲和最近成功时间 |
| T2-03 | 同步期间操作主 EA | 主 EA 按钮立即响应，报价和 Tick 管理持续运行 |
| T2-04 | 点击同步 EA“同步数据” | 第一次点击显示风险说明与“确认同步/取消”；确认后才执行 |
| T2-05 | 账户有持仓时自动同步 | 同步照常执行，不再等待空仓；主 EA 持仓保护不受阻塞 |
| T2-06 | 使用错误密钥 | 只在同步 EA 显示失败/配置问题，主 EA 继续工作 |
| T2-07 | API URL 指向不可达地址 | 同步 EA 等待超时并进入退避；主 EA 始终可操作 |
| T2-08 | 同账户挂两个同步 EA | 只有一个获得租约；另一个显示“已有同步服务运行” |
| T2-09 | 重启主 EA | `MQL5/Files/TradeEZ/instances` 中重新生成当前实例清单 |
| T2-10 | 移除同步 EA | 主 EA 的交易、追踪和风控不受影响 |

## 4. 已自动验证

- `tradeEZ.mq5`：0 errors、0 warnings。
- `tradeEZSync.mq5`：0 errors、0 warnings。
- 主 EA 静态搜索不存在 `WebRequest(`、同步输入参数和同步按钮。
- 同步 EA 静态搜索不存在下单、改单、平仓或撤单调用。
- 两个 EX5 均已生成。

## 5. 尚需后端联调

当前版本先保持现有 API 的平仓时间兼容流程，已完成事件线程隔离。下列两项必须配合后端升级后才能最终关闭第 2 项：

1. 将增量游标升级为 `deal_time_msc + deal_ticket`，验证长时间持仓、同毫秒多成交和边界重传不漏单。
2. 让 `/api/v1/ingest/settings` 接受 `instance_id`、`symbol`、`ea_version` 和 `schema_version`，验证同账户多主 EA 实例不会互相覆盖。

在后端升级前，不应宣称增量同步已达到完全无漏单保证。
