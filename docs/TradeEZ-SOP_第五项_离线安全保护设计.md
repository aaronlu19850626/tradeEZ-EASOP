# TradeEZ-SOP 第五项：离线安全保护设计

> 状态：P5-D01 至 P5-D10 已确认，专项运行验证通过并完成交付  
> 范围：服务器初始保护、保护复核、失败修复与安全退出；不承诺终端离线后继续动态追踪

## 1. 目标与承诺边界

本项只承诺一件可被交易服务器独立执行的能力：TradeEZ 新建或接管的策略仓位，在 EA、MT5 或电脑停止运行后，仍保留最后一次经服务器状态复核确认的止损；剥头皮新单在配置固定止盈时，同时确认初始止盈。

本项不承诺离线期间继续计算浮盈峰值、移动止损、超时平仓、趋势减仓或利润护城河。这些动作必须依赖 EA 在线运行。固定服务器止损是离线兜底，不替代在线动态管理。

## 2. 当前实现审计

### 2.1 已具备能力

- 市价剥头皮单在首次请求中携带固定 SL/TP；趋势单携带固定 SL。
- 限价挂单在挂单请求中携带 SL/TP，终端离线后由交易服务器保留。
- 在线追踪会尝试将 SL 向降低风险的方向推进。
- 启动恢复可以识别当前策略持仓，并对缺失逐票状态执行保守接管。

### 2.2 已确认缺口

| 编号 | 缺口 | 风险 |
|---:|---|---|
| P5-01 | `CTrade` 方法返回 `true` 后未复核服务器持仓/挂单字段 | 请求已接受可能被误认为保护已完成 |
| P5-02 | 成交事务只保存状态和重算风控，没有检查实际 SL/TP | 成交后可能存在无保护窗口 |
| P5-03 | 无保护修复状态、重试节流和最终失败处置 | 网络或券商拒绝后可能长期裸仓 |
| P5-04 | `NormalizePrice()` 只按小数位归一化，没有按 tick size 对齐 | 部分品种可能返回 invalid price/stops |
| P5-05 | 开仓前未完整校验 SL 距离、方向和参数必须大于零 | 配置错误可能产生无 SL 请求或整单拒绝 |
| P5-06 | 挂单创建后不持续检查其服务器 SL/TP | 被外部修改或异常剥离后仍可能触发 |
| P5-07 | 移动止损调用成功后不复核实际 SL，也不记录最后确认值 | 重启后无法证明最后的服务器保护位置 |
| P5-08 | “撤止盈/改趋势”只保留当时读取的 SL，未先确认该 SL 有效 | 极端情况下可能撤掉最后一个确定退出条件 |
| P5-09 | 手工删除或放宽策略仓位 SL 后，EA 没有最低保护审计 | 用户误操作会破坏离线兜底 |
| P5-10 | 当前逻辑以逐 ticket 和部分平仓为核心，未声明净额账户边界 | 净额账户混仓可能无法保证策略归属和独立保护 |

## 3. 目标保护模型

### 3.1 保护状态

| 状态 | 含义 | 是否允许新增风险 |
|---|---|---|
| `PROTECTION_CHECKING` | 新成交、启动或交易事务后等待服务器状态核对 | 否 |
| `PROTECTION_CONFIRMED` | 当前服务器 SL 满足最低保护要求 | 是 |
| `PROTECTION_REPAIR_PENDING` | SL 缺失或弱于最低要求，正在非阻塞修复 | 否 |
| `PROTECTION_CLOSE_PENDING` | 修复超时，正在安全退出该仓位 | 否 |
| `PROTECTION_FAILED` | 无法确认修复或退出，需要人工处理 | 否 |

状态按持仓独立保存。全局只要存在一个由本实例管理且未确认保护的仓位，就禁止新的市价单和挂单，但仍允许平仓、撤单及收紧 SL。

### 3.2 最低保护线

- 剥头皮多单：`开仓价 - Inp_ScalpSL_Points × 0.01`；空单方向相反。
- 趋势多单：`开仓价 - Inp_TrendSL_Points × 0.01`；空单方向相反。
- 已经由服务器确认过更优的动态 SL 永远优先，系统不得把它放宽回初始线。
- 买单 SL 越高越安全；卖单 SL 越低越安全。比较时使用 tick size 容差。
- 市价成交的初始绝对 SL 受成交滑点影响。首次请求仍附带基于当前报价计算的 SL；成交后以实际开仓价重算最低保护线，只允许补强，不主动放宽已存在的 SL。

### 3.3 TP 规则

- SL 是所有 TradeEZ 策略仓位的强制保护，不能配置为 0 或负数。
- 剥头皮 `Inp_ScalpTP_Points > 0` 时，新单和新挂单必须确认初始 TP；配置为 0 时视为产品明确关闭固定 TP。
- 趋势单不要求固定 TP。
- TP 仅在入场阶段确认。本项不会在用户执行“追踪持有/改趋势”后自动补回 TP，相关最终语义由第 7 项完成。
- 清除剥头皮 TP 前必须先确认当前服务器 SL 有效；否则拒绝操作并提示先恢复保护。

## 4. 执行流程

### 4.1 参数与券商规则预检

初始化及每次开仓前检查：

1. 策略 SL 参数必须大于 0；手数、报价和 tick size 必须有效。
2. 价格必须按 `SYMBOL_TRADE_TICK_SIZE` 对齐，而不只按 `_Digits` 截断。
3. 初始 SL/TP 的方向和距离必须满足 `SYMBOL_TRADE_STOPS_LEVEL`。
4. 配置距离不满足券商最小距离时拒绝开仓，不静默扩大最大亏损。
5. 不采用“先裸仓、成交后再补 SL”的兼容回退。

### 4.2 市价单

1. 首次下单请求必须携带初始 SL，以及剥头皮配置的 TP。
2. 检查 `ResultRetcode()`，不能只读取方法布尔返回值。
3. `OnTradeTransaction` 捕获成交/持仓变化后登记 `PROTECTION_CHECKING`。
4. 从实际持仓读取 ticket、position identifier、开仓价、SL、TP，并核对最低保护。
5. 保护满足则写入 `PROTECTION_CONFIRMED` 和最后确认 SL/TP。
6. 保护缺失或偏弱则进入非阻塞修复；不得在事件回调中 `Sleep()`。

### 4.3 限价挂单

1. 提交时附带服务器 SL/TP，并检查返回码。
2. 创建后从订单池复核 `ORDER_SL/ORDER_TP`。
3. 定时审计本实例策略挂单；保护缺失、方向错误或弱于配置时，优先修复挂单。
4. 修复不能及时完成则撤销该挂单，避免它在终端离线时成交为裸仓。
5. 挂单触发成交后立即转入市价仓位保护核对流程。

### 4.4 修复与安全退出

- 第一次发现异常立即尝试设置保护，随后按 1 秒、2 秒、4 秒节流重试；事件线程不阻塞。
- 从首次发现起 8 秒内仍无法确认有效 SL，进入 `PROTECTION_CLOSE_PENDING`，强制退出该策略仓位。
- 平仓请求提交后继续核对仓位是否仍存在；仍存在时按节流重试，不把“已提交”显示为“已完成”。
- 市场关闭、无报价或交易权限关闭导致无法修复/平仓时，进入 `PROTECTION_FAILED`：持续禁开、面板红色告警、日志记录 retcode，并保留人工平仓入口。
- 新 Tick、Timer、交易事务和启动恢复都会驱动状态机，不采用连续同步轮询。

## 5. 启动恢复与外部修改

启动恢复完成历史和逐票状态加载后，先执行服务器保护审计，再允许用户确认恢复并重新开仓：

- 当前服务器 SL 更优：接受服务器值并更新“最后确认 SL”，绝不放宽。
- 当前服务器 SL 缺失或偏弱：进入修复；修复失败按安全退出规则处理。
- 用户手工放宽或删除 TradeEZ 策略仓位 SL：视为保护破坏，EA 自动恢复最低线或最后确认的更优线。
- 手工单、其他 EA 的仓位不由本项自动修改或强平。
- 本实例的策略挂单在启动时同样审计；不安全挂单不能继续保留。

## 6. 账户模式边界

当前产品的逐票策略识别、同品种多仓、按 ticket 减仓和独立保护建立在对冲账户语义上。第五项建议正式声明：

- 对冲账户：完整支持。
- 净额账户：当前版本禁止新增交易，只允许面板展示和人工处理，不声称支持策略隔离。

在未来专门完成净额账户的合仓归属、加权开仓价和保护合并规则之前，不应以“可能能下单”代替商业支持。

## 7. 持久化字段建议

逐票状态 schema 从 V2 升级，新增：

- `protection_status`
- `minimum_required_sl`
- `last_confirmed_sl`
- `last_confirmed_tp`
- `protection_first_failed_utc_msc`
- `protection_next_retry_utc_msc`
- `protection_retry_count`
- `protection_last_retcode`

加载旧 V2 文件时进行受限迁移：不相信本地字段直接宣称保护成功，必须以当前服务器持仓 SL/TP 重新确认。

## 8. 界面和告警

- 正常：策略状态保持“就绪（可开仓）”。
- 修复中：状态显示“保护修复中”，禁止全部新增风险按钮。
- 安全退出中：显示“保护失败·正在退出”。
- 无法退出：红色显示“保护异常·请立即人工处理”，并显示受影响 ticket 数。
- 相同 ticket、相同原因限频告警，状态变化时立即告警，避免每秒弹窗刷屏。
- 专家日志必须包含 ticket、期望 SL、实际 SL、retcode、重试次数和最终结果。

## 9. 专项验收场景

| 编号 | 场景 | 通过标准 |
|---:|---|---|
| P5-01 | 剥头皮市价多/空 | 成交后服务器 SL/TP 均存在且满足配置 |
| P5-02 | 趋势市价多/空 | 成交后服务器 SL 存在、TP 为 0 |
| P5-03 | 剥头皮/趋势限价单 | 订单池中的 SL/TP 正确，触发后持仓保护继续确认 |
| P5-04 | SL 参数为 0 或负数 | 初始化失败或明确禁开，不产生裸仓 |
| P5-05 | 配置 SL 小于券商最小距离 | 明确拒绝，不自动扩大风险、不裸仓回退 |
| P5-06 | 模拟服务器首次拒绝修改 SL | 非阻塞重试，成功后才恢复开仓 |
| P5-07 | 持续拒绝 SL | 8 秒后进入安全退出，最终仓位消失或明确进入人工处理告警 |
| P5-08 | 手工删除/放宽策略仓位 SL | 自动恢复最低线或最后确认的更优线 |
| P5-09 | 手工收紧 SL | EA 接受更优值，后续绝不放宽 |
| P5-10 | 删除挂单 SL | EA 修复；不能修复则撤单 |
| P5-11 | 断网后立即关闭 MT5 | 已成交仓位和挂单在服务器端仍保留已确认 SL/TP |
| P5-12 | 启动时存在无 SL 策略仓位 | 先修复/退出，未确认前禁止开仓 |
| P5-13 | 清除 TP 时 SL 无效 | 操作被拒绝，TP 保留并提示原因 |
| P5-14 | 净额账户加载 EA | 禁止新增交易并明确显示不支持原因 |
| P5-15 | 价格 tick size 非十进制小数位 | 所有 SL/TP 对齐 tick size，无 invalid price |
