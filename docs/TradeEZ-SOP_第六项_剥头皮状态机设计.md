# TradeEZ-SOP 第六项：剥头皮状态机设计

> 状态：模拟账户专项验证通过；源码提交 `37ccdae` 已推送至 `origin/main`  
> 范围：剥头皮逐票阶段、峰值追踪、超时与退出请求；“改趋势/撤止盈”的产品语义留到第 7 项

## 1. 本项目标

把当前依赖数组是否存在、条件分支顺序和即时浮盈的隐式行为，改成逐票、可持久化、只能向前转换的剥头皮状态机。核心保证是：一旦峰值追踪激活，价格跌回启动阈值以下也不会退回初始阶段，历史峰值不会下降，退出条件不会因重启或分支提前返回而失效。

## 2. 当前实现审计

### 2.1 已具备能力

- 使用 Bid/Ask 按方向计算真实可平仓浮盈点数。
- 达到 `Inp_ScalpBETrigger` 后建立逐票峰值记录。
- 峰值只在浮盈创新高时更新。
- 根据“峰值减回撤阈值”推进服务器 SL，且第五项已确保 SL 只收紧不放宽。
- 可选绝对持仓时长限制，取消标记已经持久化。
- 追踪激活标记和峰值已进入逐票状态文件。

### 2.2 已确认问题

| 编号 | 当前问题 | 直接后果 |
|---:|---|---|
| P6-01 | 每个 Tick 都先判断当前浮盈是否仍高于启动阈值 | 已激活后跌回阈值以下会提前返回，不再执行本地回撤退出 |
| P6-02 | “数组中存在”同时承担追踪阶段含义，没有显式阶段字段 | 代码无法清楚表达初始、追踪和退出中的互斥状态 |
| P6-03 | 回撤和超时触发后每个 Tick 都直接调用 `PositionClose()` | 拒单时可能无节制重复请求，且没有退出原因和待处理状态 |
| P6-04 | 超时检查优先于追踪状态 | 已进入盈利追踪的订单仍可能因原始时间上限被强平 |
| P6-05 | “峰值追踪启动”日志会在追踪中的每个 Tick 重复打印 | 专家日志噪声大，关键状态变化不突出 |
| P6-06 | 激活和峰值首次更新分两次保存 | 极端中断窗口可能只保存激活标志而未保存首次峰值 |
| P6-07 | 参数只在运行中使用，未校验启动阈值、回撤点数和超时时间 | 非法参数可能形成无法退出或立即退出的状态 |
| P6-08 | 关闭请求成功只看方法调用，没有逐票退出阶段 | 请求提交和仓位最终消失仍然混在一起；完整核销将在第 8 项扩展 |

## 3. 目标状态机

| 状态 | 含义 | 允许转换 |
|---|---|---|
| `SCALP_INITIAL` | 已有服务器初始保护，尚未达到追踪启动线 | `TRAIL_ACTIVE`、`EXIT_PENDING` |
| `SCALP_TRAIL_ACTIVE` | 追踪已永久激活，维护单调峰值和服务器锁盈 SL | `EXIT_PENDING` |
| `SCALP_EXIT_PENDING` | 已触发回撤或超时退出，等待仓位最终消失 | `CLOSED` |
| `SCALP_CLOSED` | 仓位已不存在，仅作为短期审计记录保留 | 无 |

状态不得从 `TRAIL_ACTIVE` 回到 `INITIAL`，也不得从 `EXIT_PENDING` 回到任何持仓管理状态。

## 4. 逐 Tick 行为

### 4.1 初始阶段

1. 先确认仓位和第五项服务器保护状态有效。
2. 计算当前方向化浮盈点数。
3. 若启用超时且达到绝对截止时间，进入 `EXIT_PENDING(TIMEOUT)`。
4. 若浮盈未达到启动阈值，保持 `INITIAL`。
5. 若浮盈达到阈值，在一次原子状态保存中同时写入 `TRAIL_ACTIVE` 和首次峰值。

### 4.2 追踪阶段

1. 不再检查“当前浮盈是否仍高于启动阈值”。
2. `peak = max(saved_peak, current_profit)`，峰值只能增加。
3. 计算 `pullback = peak - current_profit`。
4. 回撤达到阈值后进入 `EXIT_PENDING(PULLBACK)`。
5. 未触发退出时，目标 SL 为开仓价加/减 `max(0, peak - trail_step)`；只在比服务器现有 SL 更安全时提交。
6. 原固定 TP 默认继续保留，是否撤除只响应用户明确操作。

### 4.3 退出阶段

- 首次进入时立即提交一次平仓请求并记录原因、时间和 retcode。
- 仓位仍存在时按 1 秒节流重试，不在每个 Tick 无边界重复。
- 仓位消失后进入 `CLOSED` 并保存最终状态。
- 第 8 项将在此基础上加入统一请求账本、成交核销和残仓处理；第 6 项只实现避免回退和重复风暴所需的最小闭环。

## 5. 超时规则建议

推荐把超时定义为“初始剥头皮未能及时进入盈利追踪时的时间止损”：

- 仅 `SCALP_INITIAL` 状态受 `Inp_ScalpMaxHoldSecs` 约束。
- 一旦进入 `TRAIL_ACTIVE`，自动免除超时，因为订单已经满足盈利质量门槛并具有服务器锁盈保护。
- 用户主动取消超时仍只影响当前 ticket，并继续持久化。
- 截止时间始终等于开仓服务器时间加配置秒数，重启不重新计时。

这样可以避免一张已经形成盈利趋势的剥头皮单，因为最初的 120 秒标签被机械平仓。

## 6. 持久化与迁移

逐票文件从 V3 升级到 V4，新增：

- `scalp_phase`
- `scalp_exit_reason`：`NONE`、`TIMEOUT`、`PULLBACK`
- `scalp_exit_requested_utc_msc`
- `scalp_exit_next_retry_utc_msc`
- `scalp_exit_retry_count`
- `scalp_exit_last_retcode`

V3 迁移规则：

- `scalp_track_active=true` → `SCALP_TRAIL_ACTIVE`，沿用已保存峰值。
- `scalp_track_active=false` → `SCALP_INITIAL`。
- 当前已不存在的票据 → `SCALP_CLOSED`。
- 迁移后仍以当前持仓 identity 和服务器 SL 为准，不因本地记录放宽保护。
- 每日风控全局变量继续沿用既有 V2 命名空间，不随逐票 schema 升级。

## 7. 日志与界面

- 仅在状态变化时记录“追踪激活”“触发回撤退出”“触发超时退出”“最终关闭”。
- 峰值日志按至少 10 个标准点的增量限频，避免每 Tick 刷屏；逐票文件仍保存真实峰值。
- 明细或专家日志显示退出原因、峰值、触发时浮盈、回撤值和服务器 SL。
- 当前策略卡片不增加复杂控件；如存在 `EXIT_PENDING`，运行状态显示“剥头皮退出处理中”。

## 8. 参数校验

以下条件不满足时禁止初始化交易能力：

- `Inp_ScalpBETrigger > 0`
- `Inp_ScalpTrailStep > 0`
- 启用超时时 `Inp_ScalpMaxHoldSecs > 0`
- 启动阈值和回撤阈值必须为合理整数范围，避免溢出。

允许 `trail_step >= trigger`，其含义是追踪刚激活时服务器 SL 可能仍停留在初始保护或保本附近；系统不会为追求形式上的锁盈而扩大风险。

## 9. 专项验收场景

| 编号 | 场景 | 通过标准 |
|---:|---|---|
| P6-01 | 浮盈未达启动线 | 始终处于 `INITIAL`，峰值未伪造 |
| P6-02 | 恰好达到启动线 | 单次进入 `TRAIL_ACTIVE`，首次峰值原子保存 |
| P6-03 | 激活后跌回启动线以下 | 仍保持 `TRAIL_ACTIVE`，继续计算历史峰值回撤 |
| P6-04 | 多次创新高 | 峰值单调增加，SL 只向安全方向推进 |
| P6-05 | 达到回撤阈值 | 单次进入 `EXIT_PENDING(PULLBACK)`，不发生每 Tick 请求风暴 |
| P6-06 | 初始阶段达到超时 | 进入 `EXIT_PENDING(TIMEOUT)` |
| P6-07 | 激活后超过时间上限 | 不再触发超时，继续按追踪管理 |
| P6-08 | 用户取消超时后重启 | 取消状态保持，不触发超时退出 |
| P6-09 | `EXIT_PENDING` 时重启 | 继续核对和退出，不恢复到追踪或初始状态 |
| P6-10 | V3 活跃追踪票据升级 | 正确迁移为 `TRAIL_ACTIVE`，峰值不丢失 |
| P6-11 | V3 未激活票据升级 | 正确迁移为 `INITIAL` |
| P6-12 | 平仓请求首次被拒 | 1 秒节流重试，界面明确显示处理中 |
| P6-13 | 固定 TP 先成交 | 仓位消失后进入 `CLOSED`，不再提交回撤平仓 |
| P6-14 | 重启时当前浮盈高于启动线但旧状态缺失 | 按保守恢复规则接管并要求确认，不伪造离线峰值 |
| P6-15 | 非法剥头皮参数 | 初始化明确失败，不进入不确定状态 |
