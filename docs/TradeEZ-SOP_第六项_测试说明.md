# TradeEZ-SOP 第六项测试说明

> 目标：验证剥头皮订单的阶段只能向前推进，激活后不失效，峰值不回退，退出请求能够可靠收敛。  
> 环境：仅使用模拟账户；建议临时调小参数以缩短测试时间，测试后恢复正式配置。

## 1. 测试前准备

1. 将最新 `tradeEZ.ex5` 加载到模拟账户图表，确认专家日志没有初始化错误。
2. 使用对冲账户，并保持自动交易开启。
3. 为便于观察，可临时设置：启动阈值 `30`、回撤点数 `15`、启用超时、超时秒数 `30`。
4. 每个场景尽量只保留一张剥头皮仓位，避免不同订单的日志混在一起。
5. 重点观察专家日志中的 `[Scalp State]`、`[Scalp Peak]`、`[Scalp Exit]` 和 `[State V4]`。

## 2. 必测场景

### A. 激活后不回退

1. 开一张剥头皮单，让浮盈达到启动阈值。
2. 确认日志只出现一次 `INITIAL -> TRAIL_ACTIVE`。
3. 让价格回落到启动阈值以下，但尚未达到峰值回撤退出线。

通过标准：订单继续处于追踪状态；不会恢复初始阶段；动态止损不会向风险方向放宽。

### B. 峰值单调与回撤退出

1. 激活追踪后让价格多次创新高。
2. 记录最高浮盈和服务器端止损位置。
3. 让价格从最高浮盈回撤达到配置点数。

通过标准：峰值只增不减；止损只收紧；达到回撤线后显示“剥头皮退出处理中”，立即发起平仓，最终仓位消失。

### C. 初始阶段超时

1. 启用超时并设置较短秒数。
2. 开仓后让订单始终未达到追踪启动线。

通过标准：截止时间到达后进入 `EXIT_PENDING(TIMEOUT)` 并平仓；日志记录退出原因“超时”。

### D. 激活后免除超时

1. 启用短超时并开仓。
2. 在截止时间前让订单进入追踪状态。
3. 持仓超过原超时时间，但不触发峰值回撤。

通过标准：订单不会因原超时时间被强平，继续由峰值回撤和服务器保护管理。

### E. 重启恢复

1. 在订单进入追踪且形成峰值后，移除 EA 再重新加载。
2. 再次让价格回落到启动线以下或达到峰值回撤线。

通过标准：日志显示 `[State V4]` 有效恢复；阶段和历史峰值不丢失；不会重新打印第二次激活；达到回撤线仍能退出。

### F. 固定止盈与手动撤止盈

1. 追踪激活后检查服务器端 TP。
2. 不点击“撤止盈”，确认 TP 保留。
3. 另开一单并在追踪激活后点击“撤止盈”。

通过标准：系统不自动撤 TP；只有用户明确操作时才撤除，且退出处理中不再改变退出条件。

### G. 参数拒绝

分别把启动阈值、回撤点数设为 `0`，以及在启用超时时把超时秒数设为 `0` 后加载 EA。

通过标准：EA 返回参数错误，不进入交易管理；专家日志明确指出策略保护、追踪或超时参数无效。

## 3. 建议补测

- 在追踪激活、退出处理中分别重启 MT5，确认阶段不倒退。
- 在退出时临时关闭自动交易，观察平仓按不高于每秒一次的频率重试；恢复自动交易后应最终平仓。
- 让固定 TP 先成交，确认本地状态转为 `CLOSED`，不再继续发送平仓请求。
- 从旧 V3 状态升级时，确认活跃追踪票据迁移为 `TRAIL_ACTIVE` 且峰值保留。

## 4. 回归检查

- 剥头皮市价、限价和快捷挂单仍能正常建立服务器 SL/TP。
- 趋势单的移动止损、减仓和退出行为不受本项影响。
- 一键全平、平剥头皮、平趋势和平盈利单仍可使用。
- 日熔断、分策略熔断、恢复确认和服务器保护失败处置仍按原规则运行。
