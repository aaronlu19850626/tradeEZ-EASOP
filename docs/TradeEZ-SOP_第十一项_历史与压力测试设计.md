# TradeEZ-SOP 第十一项：历史与压力测试设计

> 状态：设计待确认，尚未修改 `tradeEZ.mq5`。
>
> 目标：让核心交易、保护、风控、恢复和周期逻辑在 MT5 策略测试器中自动执行，输出可复现、可审计的 PASS/FAIL 结果；同时明确哪些项目必须在开市后的模拟账户补验。

## 1. 当前问题

1. 当前交易入口主要位于 `OnChartEvent()`，依赖图表按钮点击。MT5 官方限制明确指出：策略测试器即使开启可视化，也不会向 EA 派发交互式图表、对象、键盘和鼠标事件。因此看到按钮不代表点击事件会进入 EA；截图中的按钮无法点击属于平台行为，不是按钮坐标或布局缺陷。
2. 现有 EA 没有测试场景选择、测试步骤状态机、断言、超时判定、自动清理和统一报告。
3. 人工查看日志只能证明“看起来执行过”，不能稳定证明请求、成交、保护位、持仓状态和内部账本最终一致。
4. 休市时真实图表没有新 Tick，不能新开或平仓；但策略测试器会回放工作日的历史 Tick，因此周末仍可完成大多数功能验证。
5. 策略测试器无法真实复现券商网络延迟、真实断线、服务器异步乱序、流动性不足和真实部分成交，这些必须单列为开市后的模拟账户补充测试。

### 1.1 截图现象的两层原因

- `OnChartEvent()` 在 EA 策略测试器中不被调用，所以做空、做多、平仓、重置等按钮都不会触发对应分支；
- 测试器当前历史时刻显示“休市（禁开）”，即使事件能够到达，新增交易也会被交易时段门控拒绝。该门控不应通过修改代码绕过。

结论：测试器不能用鼠标按钮验证交易功能，必须使用后续的自动场景驱动；按钮本身仍应在真实图表或模拟账户中验收。

## 2. 测试架构

### 2.1 测试器专用入口

在主 EA 中增加测试器专用输入组，默认完全关闭：

- `Inp_TestScenario`：`OFF / SMOKE / SCALP / TREND / RISK / BATCH / PERIOD / RECOVERY_A / RECOVERY_B / FULL`；
- `Inp_TestSeed`：固定随机种子，保证同一数据和参数下可复现；
- `Inp_TestMaxSeconds`：单场景超时；
- `Inp_TestBatchSize`：批量订单规模，首版限制为 1～100；
- `Inp_TestRunId`：报告和状态隔离标识；
- `Inp_TestAutoCleanup`：结束时撤销本轮测试挂单并平掉本轮测试持仓。

硬性安全门：

1. 只有 `MQL_TESTER=true` 时允许测试场景运行；
2. 实盘或普通模拟图表只要 `Inp_TestScenario != OFF`，EA 必须拒绝初始化并明确告警；
3. `OFF` 时不改变当前生产行为；
4. 测试驱动不得调用一套简化交易实现，必须复用正式的开仓、挂单、请求账本、风控、保护、追踪和平仓函数。

### 2.2 场景状态机

每个场景采用非阻塞步骤状态机：

`WAIT_MARKET → ARRANGE → ACT → WAIT_RESULT → ASSERT → CLEANUP → DONE/FAILED`

- 由 `OnTick()` 和 1 秒安全时钟推进；
- 每一步有明确前置条件、成功条件和超时条件；
- 不使用 `Sleep()`；
- 不依赖人工点击或模态确认框；
- 请求已提交但结果未核销时不得提前判定成功；
- 场景结束必须核对服务器事实、交易请求账本和逐票状态三者一致。

### 2.3 断言与报告

每条断言输出：

- 用例编号、场景、步骤；
- 预期值与实际值；
- 账户、服务器、品种、时间周期、Tick 模型、历史区间；
- EA 版本、输入参数摘要、测试时区和 Run ID；
- 请求 ID、订单号、成交号、持仓票号；
- PASS / FAIL / SKIP 及原因；
- 总用时、最大持仓数、最大挂单数、最大未核销请求数；
- 测试结束时残仓、残单和未完成请求数量。

输出两份文件：

1. 便于阅读的 Markdown 报告；
2. 便于后续汇总的 CSV 明细。

只要发生以下任一情况，整轮不得显示 PASS：断言失败、步骤超时、历史不足、账户模式不符、报价失效、请求账本未清、存在本轮测试残仓或残单。

## 3. 场景清单

| 组别 | 用例 | 自动化目标 |
|---|---|---|

| SCALP-TP | H-20～H-23 | 未授权撤 TP 自动恢复、追踪持有后 TP 保持为零、手工重设后恢复强制保护 |

## 4. 压力测试原则

1. 首版单轮上限 100 个订单请求，默认 20；超过 100 不允许启动，避免测试器或误配置失控。
2. 批量场景使用最小合法手数，并在测试前检查保证金和配置风险上限；不能为了制造数量而绕开正式风控。
3. 分别记录“提交峰值”和“最终服务器事实”，不能把 `OrderSendAsync()` 返回成功当作成交成功。
4. 同时覆盖快速 Tick、跳空、扩大点差和长时间无 Tick 数据段。
5. 测试结束执行有界清理；清理失败必须 FAIL，并在报告首屏列出残留票据。
6. 优化器并行测试暂不作为首版支持范围，第一版只支持单次本地测试器运行，避免多个测试代理竞争文件与状态。

## 5. 周末可完成与不可完成的测试

### 5.1 周末可完成

使用策略测试器回放周一至周五的历史 Tick，可完成：

- 市价单、挂单、平仓和撤单的逻辑验证；
- 剥头皮与趋势状态机；
- 服务器 SL/TP 在测试器成交模型中的确认与修复；
- 风险容量、熔断、批量订单和请求账本；
- 跨 04:50、跨自然周、日报和恢复文件；
- 面板展示检查，但不把鼠标点击作为自动化验收依据。

### 5.2 必须开市后补验

- 真实模拟服务器的拒单、滑点、执行延迟和异步事务顺序；
- 人为断网、恢复联网以及终端进程被强制结束后的真实恢复；
- 券商是否产生部分成交，以及部分成交后的补差和残仓处理；
- 实盘图表按钮、确认框、手型光标和真实成交联动；
- 极端行情下服务器侧 SL/TP 的实际执行质量。

这些项目单独标记为 `LIVE-SUPPLEMENT`，不会因为周末无法执行而阻塞历史测试开发，但商业化交付前必须通过。

## 6. 周末测试操作方案

在自动测试入口完成前，可先验证现有自动管理逻辑；完成后按同一方式选择场景即可：

1. MT5 按 `Ctrl+R` 打开“策略测试器”。
2. EA 选择 `Gold SOP\\tradeEZ.ex5`，不要选择根目录中的旧副本。
3. 品种选择真实使用品种（当前为 `GOLD#`），周期选择 `M1`。
4. 模式选择“每个基于真实 Tick 的 Tick”。不要使用“仅开盘价”。
5. 日期选择已有历史 Tick 的工作日，例如 `2026-09-14` 至 `2026-09-18`；不要只选择周六、周日。
6. 开启可视化以观察面板；自动报告测试可关闭可视化提高速度。
7. `Inp_TesterServerUtcOffsetHours` 必须填写该历史区间的交易服务器 UTC 偏移。XM 服务器在 9 月通常采用夏令时偏移，建议先用 `+3`，并以测试日志中的服务器时间和北京时间换算结果核对；冬夏令时跨界区间应拆成两次测试。
8. 初期使用正常速度；批量压力场景再提高速度。结束后检查“专家”日志以及 `MQL5/Files` 下的 PASS/FAIL 报告。

策略测试器播放的是历史工作日行情，因此电脑当前处于周末、市场报价栏显示休市，都不影响历史回测。若选中的区间只有周末或本地没有下载到 Tick，测试会没有行情推进，应换成工作日并先下载历史数据。
