# TradeEZ-SOP 第十项：每日初始化与周计划设计

> 状态：P10-D01 至 P10-D14 已确认并完成开发、编译，等待专项验证  
> Git 基线：`55e84ec`（第九项已推送至 `origin/main`）

## 1. 目标

建立唯一、幂等、可恢复的统计周期引擎，确保 EA 在线跨日、终端休眠、MT5 关闭后重启、手动重置及回测场景得到一致结果：

- 每日统计按北京时间 04:50 切换；
- 自然周按北京时间周一 00:00 开始；
- 错过切换时刻后可以安全补做，不重复清空、重复导出或遗漏周期；
- 周计划始终从历史重建，不依赖某次每日初始化是否执行；
- 跨日持仓的逐票管理状态不清零；
- 历史不完整时失败关闭，只允许退出风险。

## 2. 当前实现中确认的问题

### 2.1 在线跨日与启动恢复不是同一条路径

`CheckDayRollover()` 在线跨日时直接导出并清空状态；启动恢复则使用 `ReplayMissedPeriods()` 和 `BuildRecoverySnapshot()`。两套路径的失败处理、报告格式和状态提交顺序不一致。

### 2.2 日报被手动重置截断

官方日报当前使用 `StatStart()`。用户当天手动重置后，`StatStart()` 变成手动重置时刻，导致该统计日 04:50 至手动重置之间的交易从日报中消失。

### 2.3 日初余额无法正确处理其他品种与资金流水

启动恢复目前采用：

```text
当前账户余额 - 当前品种本周期已实现盈亏
```

它没有扣除其他品种交易、入金、出金、手续费、利息、红利和余额调整，因此“今日初始金额”可能错误。

### 2.4 盈亏口径遗漏部分交易成本

多处统计只扫描 `DEAL_ENTRY_OUT`，容易遗漏开仓成交收取的佣金及 `DEAL_FEE`。风险、日报和周计划可能因此高估收益。

### 2.5 报告失败与周期完成状态耦合不严谨

在线跨日中，即使报告文件创建失败，也可能继续推进 `g_LastReportedPeriod` 和新周期状态。重启后无法判断报告究竟成功还是遗漏。

### 2.6 报告文件命名存在覆盖风险

当前文件名只有账户和日期。同一账户运行多个品种或多个实例时可能覆盖彼此报告。

### 2.7 周计划提示已经失去可见入口

`WeeklyHint()` 仍存在，但第九项 UI 调整后主面板只显示周进度，未再显示档位建议。

### 2.8 回测时区没有显式输入

当前通过测试环境时间函数差值推断服务器偏移，不满足既定基线“回测显式配置历史服务器 UTC 偏移”。在经纪商夏令时切换附近也可能产生一小时边界偏差。

## 3. 推荐的数据口径

### 3.1 两条互不混淆的时间线

```text
official_period_start = 北京时间每日 04:50
risk_baseline_start   = max(official_period_start, 当天最后一次手动重置时刻)
week_start            = 北京时间周一 00:00
```

- 官方日报始终覆盖完整的 `official_period_start ~ next_period_start`。
- 主面板风控盈亏、连亏、高水位允许从 `risk_baseline_start` 重新开始。
- 手动重置不改变官方日报和周计划，不删除历史，只改变当日后续风控基线。

### 3.2 交易现金盈亏

对统计区间内当前品种的全部交易成交累加：

```text
DEAL_PROFIT + DEAL_SWAP + DEAL_COMMISSION + DEAL_FEE
```

- 风控和周计划采用现金发生制，保证每笔费用只计算一次；
- 包含手动单和其他 EA；
- 入金、出金、信用额及账户余额调整不计入交易盈亏；
- 胜率、持仓时长等交易质量指标仍以出场成交为事件，并把可归属成本分配到对应仓位。

### 3.3 日初账户余额

从当前余额反推统计周期起点：

```text
period_start_balance = 当前余额 - 周期内全账户所有余额变动
```

余额变动扫描所有品种的交易成交与资金类成交，包含利润、隔夜费、佣金、手续费、入出金、信用额、利息、红利、税费及余额调整。这样“账户日初余额”与“当前品种交易盈亏”明确分栏，不再混为一谈。

## 4. 统一周期事务

在线跨日、定时器发现跨日和启动恢复全部调用同一事务：

1. 计算当前官方统计周期 ID；
2. 从最后完成周期开始，按顺序枚举遗漏周期；
3. 检查所需历史是否可用；
4. 从历史构建上一周期不可变快照；
5. 用临时文件生成报告并原子替换正式文件；
6. 报告失败则记录“待补报”，但不阻止新统计日建立；
7. 从历史重建当前周期的余额基线、已实现盈亏、峰值、连亏游标及冷却状态；
8. 保留所有跨日持仓的逐票管理状态；
9. 原子保存新周期状态；
10. 最后提交 `last_completed_period`；
11. 待补报告由一秒安全时钟重试，成功后才推进 `last_reported_period`。

历史本身不可用时，不得用零值覆盖状态，EA进入“只平不开”并按配置间隔重试。

## 5. 周计划

- 周界线固定为北京时间周一 00:00，不跟随每日 04:50 重置；
- 每次从成交历史重建当前品种交易现金盈亏；
- 包含手动单和其他 EA；
- 不受手动重置影响；
- 周计划只提示纪律建议，不自动修改日回撤参数、不自动平仓；
- 结果按一秒缓存，避免一次 UI 重绘反复扫描相同历史；
- UI 合并显示为：`+$2,350 / $4,000 · 建议日回撤 $600`，恢复档位提示的可见性。

## 6. 时间与回测

- 实盘使用当前经纪商服务器偏移，并把每个已观察到的周期边界持久化；
- 策略测试器新增显式服务器 UTC 偏移参数，禁止依赖测试器内 `TimeGMT()` 差值推断；
- 对无法证明历史偏移的离线区间标记为保守恢复，不伪造精确边界；
- 周期 ID 使用北京时间日期和重置时分，不直接使用易受服务器夏令时影响的时间戳作为业务主键。

## 7. 报告命名和审计

推荐文件名：

```text
TradeEZ_<serverHash>_<login>_<symbol>_<instance>_<periodId>.md
```

报告记录：

- 北京时间统计区间；
- 账户日初余额及其重建方式；
- 当前品种交易现金盈亏；
- 手动重置时刻（若存在）；
- 数据完整性状态；
- 生成原因：在线跨日、启动补做或重试补报。

同一周期重复生成时覆盖同一文件，不产生重复报告。

## 10. 模拟账户验收顺序

建议在独立图表上使用新的 `Inp_InstanceId`（例如 `item10-test`），避免与当前正式实例共享状态。

1. **基础启动**：加载 EA，确认日志没有恢复失败，面板“周计划”同时显示本周金额、目标和建议。
2. **手动重置双基线**：记录重置前数据后点击“重置”；确认面板风控数据从当前时刻重新累计，但 MT5 历史记录没有被删除。
3. **在线跨日**：临时把每日重置时分设为北京时间未来 2～3 分钟，保持 MT5 在线跨过边界；确认只初始化一次、按钮仍可用、跨日持仓仍受原有逐票状态管理。
4. **报告检查**：在“文件 → 打开数据文件夹 → MQL5 → Files”检查 `TradeEZ_<server>_<account>_<symbol>_<instance>_<period>.md`；同一周期重复检查不得生成带序号的重复文件。
5. **离线补做**：使用另一个新实例，在边界前关闭 MT5，边界后重新启动；确认旧周期报告被补做，当前周期数据已重建，日志没有把报告失败误报成初始化失败。
6. **手动重置后跨日**：当天先手动重置再跨边界；确认报告统计区间仍从官方日界开始，并在报告中单独记录手动风控重置时刻。
7. **现金口径**：完成一笔会收取佣金/手续费的测试单；核对面板、报告净盈亏包含开仓和出场两侧费用，连续亏损判断也按完整交易净结果执行。
8. **账户余额重建**：若模拟账户支持入金/余额调整，执行一次小额调整；确认“今日初始金额”可以反推账户余额，但该资金流水不进入当前品种交易盈亏。
9. **自然周边界**：在测试器选取跨北京时间周一 00:00 的区间；确认周计划在 00:00 换周，而每日统计仍按 04:50 换日。
10. **回测时区**：把 `Inp_TesterServerUtcOffsetHours` 设置为该历史经纪商服务器的 UTC 偏移，跨过 04:50；确认面板时间、日界和报告区间一致。夏令时切换区间应拆分测试并分别使用对应偏移。
11. **参数拒绝**：令周档位 2 小于档位 1，或将测试器偏移设为范围外值；EA 应拒绝初始化并打印参数错误。
12. **重复启动幂等**：同一周期连续移除并重新加载 EA 两次；统计、高水位、周计划和报告文件应保持一致，不重复归零。

验收时请保留“专家”日志、报告文件名与关键面板截图；确认后按约定仅提交 `tradeEZ.mq5`。
