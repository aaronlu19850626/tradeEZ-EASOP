# TradeEZ-SOP 规则与验收基线

> 文档状态：待项目所有者确认  
> 基线日期：2026-09-18（北京时间）  
> 适用范围：`tradeEZ.mq5` 版本 1.03 及后续商业化重构  
> 原则：先确认规则，再修改源码；源码、界面、提示、手册和测试结果必须保持一致。

## 1. 产品定位

TradeEZ-SOP 定位为 MT5 上的半自动交易执行、持仓保护、纪律风控与复盘工具。

- 交易方向和开仓时机由用户决定，EA 不提供自动买卖信号。
- EA 可以执行市价单、限价单、批量平仓、固定保护和在线动态管理。
- EA 不承诺成交价格、盈利结果或终端关闭后的动态追踪。
- 商业版第一阶段仅支持对冲账户；净额账户在完成独立验证前明确标记为不支持。
- 交易核心必须能够在同步服务、授权服务或网页服务故障时继续管理已有持仓。

## 2. 可靠性等级定义

| 等级 | 含义 | 示例 |
|---|---|---|
| 服务器已确认 | 请求已被交易服务器确认，并能从订单/持仓状态复核 | 当前持仓 SL、TP、实际成交量 |
| 本地已执行 | EA 已完成计算并提交请求，但仍需等待服务器结果 | 批量平仓、修改 SL 请求 |
| 本地计划 | EA 计划在未来 Tick 或定时事件执行 | 峰值追踪、超时平仓、每日任务 |
| 展示信息 | UI 根据当前可用数据计算，不能替代服务器状态 | 按钮颜色、策略状态、统计提示 |

所有成功提示必须准确使用上述语义，不得将“已提交”显示为“已成交”或“已完成”。

## 3. 不可突破的产品边界

1. MT5 和 EA 停止后，只有服务器已确认的 SL、TP 和挂单继续有效。
2. 本地动态追踪、峰值回撤、超时平仓、减仓和日初始化均需要 EA 运行。
3. 重启后可以重建成交和统计，但不能精确恢复停机期间未记录的 Tick 峰值。
4. 离线安全目标是保留最后确认的服务器保护，不是假定动态管理仍在运行。
5. 网络同步、官网、更新日志和商业授权均不得阻塞或停止已有仓位的保护。

## 4. 订单操作规则

### 4.1 开仓

| 操作 | 当前行为 | 商业化目标规则 |
|---|---|---|
| 剥头皮市价单 | 固定手数，附带固定 SL/TP | 成交后核对实际仓位和服务器 SL/TP；保护失败按配置重试或平仓 |
| 趋势市价单 | 固定手数，附带 SL，无固定 TP | 同上；明确依赖在线阶梯管理 |
| 指定价格限价单 | 校验方向和最小距离后提交 GTC 挂单 | 挂单计入策略容量和风险额度；记录服务器最终结果 |
| 快捷偏移挂单 | Bid 上方挂空、Ask 下方挂多 | 保持价格语义；界面明确偏移单位为价格差，不是平台 Point |

任何新增风险操作必须检查：市场状态、交易时段、策略熔断、总熔断、连亏冷却、持仓、挂单、待确认请求、保证金、报价新鲜度和最大点差。

### 4.2 平仓和撤单范围

| 操作 | 冻结范围 | 是否撤挂单 | 结果要求 |
|---|---|---:|---|
| 一键全平 | 当前图表品种的全部持仓，包括手动单和其他 EA 单 | 是，当前品种全部挂单 | 显示目标、已完成、失败和剩余数量 |
| 平剥头皮 | 当前品种且剥头皮 Magic 的持仓 | 否 | 按票核销结果 |
| 平趋势单 | 当前品种且趋势 Magic 的持仓 | 否 | 按票核销结果 |
| 平盈利单 | 当前品种满足盈利判定的全部持仓，包括手动单和其他 EA 单 | 否 | 显示采用的盈利口径和剩余持仓 |

建议一键全平增加简短确认，确认文字必须明确“包含当前品种的手动单、其他 EA 持仓和全部挂单”。利润护城河自动清盘不显示模态确认，但必须持续核对残余仓位。

### 4.3 批量操作

- MT5 不存在单个请求同时平掉多个独立持仓；“一键”表示一次用户操作，不表示服务器一次成交。
- 批量请求必须建立请求账本，并由 `OnTradeTransaction` 和最终持仓状态共同核销。
- 失败重试必须有次数、间隔和最终失败状态，禁止无限重试。
- 已经关闭或正在平仓的 ticket 不得再次提交导致反向开仓风险。

## 5. 剥头皮策略规则

### 5.1 目标状态机

```text
NEW
  → INITIAL_PROTECTION_PENDING
  → INITIAL_PROTECTED
  → TRAIL_WAITING
  → TRAIL_ACTIVE
  → CLOSE_PENDING
  → CLOSED
```

异常状态包括：`PROTECTION_FAILED`、`RECOVERY_INCOMPLETE` 和 `MANUAL_INTERVENTION`。

### 5.2 固定规则

- 入场后必须具有服务器确认的初始 SL；剥头皮可按参数设置固定 TP。
- 追踪阈值只用于首次激活。一旦进入 `TRAIL_ACTIVE`，不得因当前浮盈跌回激活线以下而退出追踪。
- 峰值只能上升，不能回退；服务器 SL 只能向降低风险的方向移动。
- 回撤达到阈值后进入 `CLOSE_PENDING`，在最终核销前禁止重复提交无边界平仓请求。
- 超时规则使用绝对截止时间，重启不能重新开始计时。
- 追踪峰值、超时截止时间和最后确认 SL 必须按持仓独立持久化，不能随日初始化清零。

### 5.3 撤止盈与改趋势

建议商业稳定版采用以下语义：

| 功能 | 目标规则 |
|---|---|
| 追踪持有（原“撤止盈”） | 仅在追踪已激活且服务器保护 SL 已确认后撤掉固定 TP，继续使用剥头皮追踪 |
| 改趋势 | 第一版暂不提供；在真正实现管理模式、超时规则、减仓、风控归属和重启恢复的完整迁移前，不保留误导性入口 |

如果项目所有者决定保留“改趋势”，必须作为独立工作项重新定义，不得沿用当前仅清除 TP 和登记标记的行为。

## 6. 趋势策略规则

- 初始服务器 SL 必须确认成功。
- 保本、阶梯锁盈、减仓和峰值追踪是彼此独立的状态，行情跳过某个价格档位时不能跳过必要动作。
- 减仓最多成功执行一次；失败必须保留待处理状态，不能仅因调用函数返回布尔值就标记完成。
- 追踪一旦激活，即使价格跌回追踪触发线以下，也继续按历史峰值判断退出。
- 减仓后的剩余仓位继续保留正确的逐票管理状态。

## 7. 风控规则

### 7.1 普通回撤和连亏

- 剥头皮、趋势和总回撤熔断默认只禁止新增风险，不自动平仓。
- 剥头皮分项回撤熔断和趋势分项回撤熔断始终只禁止对应策略新增风险，不触发强平。
- 增加“日回撤熔断时是否强平”的用户开关，建议参数默认值为 `false`。
- 只有当前品种总日回撤达到阈值时读取该开关：关闭时只禁止新增风险；开启时平掉当前品种全部持仓并撤销当前品种全部挂单，同时持续核对残余仓位。
- 分项熔断不得读取或执行上述强平开关，避免某一策略单独触线时误清理其他持仓。
- 熔断时仍允许平仓、减仓、收紧 SL 和撤销挂单。
- 连亏按唯一成交 ticket 或毫秒时间处理，不按秒级时间简单去重。
- 冷却截止时间持久化，重启后不能重新开始或提前解除。

### 7.2 利润护城河

- “达到盈利档位”和“回撤触发清盘”是两个不同事件。
- 触发清盘后，应持续核对当前品种残余持仓和挂单，不能在请求刚提交时就认定清盘完成。
- 清盘完成后保持当日禁开，次日幂等解除。
- 目标默认值已经确认为 30%。当前 `tradeEZ.mq5` 源码仍是 300%，将在对应风控开发项中修改为 30%，在修改完成前不得将当前构建描述为已采用 30%。

### 7.3 风控作用域

当前多数所谓“全局”数据实际为当前图表品种口径。商业版第一阶段建议：

- UI 使用“当前品种风险”，不使用容易误解的“全账户风险”；
- 一键全平保持当前品种范围；
- 账户余额、净值和保证金明确标记为账户级；
- 如果未来实现全账户风控，必须由唯一实例负责，防止多个图表重复清盘。

## 8. 时间、每日初始化和周计划

### 8.1 时间口径

| 数据 | 标准时间 |
|---|---|
| 成交与持仓 | 券商服务器时间保存，同时保留 UTC |
| 每日统计 | 北京时间，默认每日 04:50 切换 |
| 自然周 | 北京时间周一 00:00 开始 |
| 网络接口 | UTC Unix 时间戳 |
| 回测 | 显式配置历史服务器 UTC 偏移，不从测试器时间函数差值推断 |

### 8.2 每日初始化

- 初始化必须幂等，同一统计日重复执行不会重复清空或重复导出。
- 终端错过 04:50 后，首次启动或首次 Tick 应补做初始化。
- 补做时从成交历史重建日初余额和已实现盈亏。
- 跨日持仓管理状态不得清零。
- 关机期间的浮盈高水位不能伪造，应标记为恢复不完整并采用保守规则。
- 漏掉的日报允许按明确历史区间补生成。

### 8.3 周计划

- 每次从成交历史重建，不依赖某次每日初始化是否执行。
- 当前目标口径建议保持“当前品种、全部平仓成交、含手动及其他 EA”。
- 净收益包含平仓利润、隔夜费和能够归属的佣金。
- 周计划只提供纪律提示，不自动改变风险参数或强制平仓。

## 9. 数据同步规则

- 主交易 EA 不得包含或调用 `WebRequest()`。
- 独立同步 EA 不得下单、改单或平仓。
- 主 EA 通过本地事件或请求标记通知同步 EA，不等待网络结果。
- 同步任务失败只影响复盘数据，不影响交易和已有持仓管理。
- 所有成交事件使用唯一 ID，服务端必须支持幂等上传。
- 同步游标只有在服务端明确确认后才推进。
- MT5 关闭期间不上传；重新启动后从本地事件和成交历史补传。
- 授权或同步密钥不得写入普通日志、截图或可公开配置摘要。

## 10. 状态持久化和恢复

- 状态命名空间至少包含：账户、服务器、品种、实例 ID 和数据版本。
- 持仓状态生命周期独立于每日统计生命周期。
- 关键状态变化后及时持久化；不在每个 Tick 无变化时重复写盘。
- 启动后先恢复审计，再允许新增交易。
- 本地状态缺失时不放宽真实服务器 SL，不伪造历史峰值。
- 状态结构升级必须提供迁移或明确的安全降级方式。

## 11. 支持范围基线

第一版商业稳定版建议正式支持：

- MT5 对冲账户；
- Windows MT5 桌面终端；
- 单账户可运行多个品种，但必须配置唯一实例 ID；
- 黄金类品种及带后缀品种，按实际合约规格计算；
- 官网版包含独立同步 EA；
- MQL5 Market 版需另行移除 DLL、外链和不符合市场规则的联网能力。

暂不承诺：净额账户、多终端同时管理同一账户、终端关闭后的动态追踪、所有券商无差异兼容。

## 12. 回归测试矩阵

| ID | 场景 | 通过条件 |
|---|---|---|
| T-01 | 剥头皮市价多/空 | 实际仓位、Magic、手数、服务器 SL/TP 全部正确 |
| T-02 | 趋势市价多/空 | 实际仓位、Magic、手数和服务器 SL 正确，无固定 TP |
| T-03 | 指定价和快捷挂单 | 价格、方向、距离和策略归属正确，挂单计入容量 |
| T-04 | 剥头皮达到阈值后跌回阈值以下 | 追踪仍保持激活，并按历史峰值处理 |
| T-05 | 趋势价格跳过多个档位 | 必要锁盈和减仓不被跳过，减仓最多一次 |
| T-06 | 撤 TP/追踪持有 | 未确认保护时拒绝；执行后 SL 保留且 TP 为零 |
| T-07 | 一键全平混合订单 | 当前品种持仓和挂单最终清零，其他品种不受影响 |
| T-08 | 分类平仓 | 只处理对应 Magic 的当前品种持仓 |
| T-09 | 平盈利单 | 盈利口径一致，亏损单和其他品种不受影响 |
| T-10 | 拒单、部分成交、断线 | 请求状态和最终持仓一致，残余风险可见 |
| T-11 | 策略分项熔断 | 只禁止对应策略新增风险，无论日熔断强平开关为何值均不强平 |
| T-11A | 总日回撤熔断，强平开关关闭 | 禁止新增风险，已有持仓继续按保护规则管理 |
| T-11B | 总日回撤熔断，强平开关开启 | 当前品种持仓和挂单最终清零，失败项持续可见且有界重试 |
| T-12 | 多挂单同时触发 | 不突破配置的总容量和风险限制 |
| T-13 | 正常关闭后重启 | 逐票状态、截止时间和最后保护位恢复 |
| T-14 | 强制结束后重启 | 进入恢复审计；缺失状态不会被静默忽略 |
| T-15 | 持仓跨 04:50 | 日统计切换，持仓追踪状态不清零 |
| T-16 | 错过 04:50 后启动 | 补做初始化和日报，不重复执行 |
| T-17 | 自然周切换 | 周一北京时间 00:00 正确换周，历史统计可重建 |
| T-18 | 同步网络超时 | 交易 EA Tick、追踪和按钮操作不受阻塞 |
| T-19 | 两个图表实例并行 | 状态、按钮、文件和全局变量互不污染 |
| T-20 | 回测模式 | 自动场景入口能够输出可复现的 PASS/FAIL 报告 |
