# TradeEZ-SOP EA 操作手册

编制日期：2026-09-18。适用源码：tradeEZ.mq5，文件头时间为 2026-09-18 15:25（北京时间），程序版本 1.03。

本手册依据当前代码编写，说明实际实现，不代表已经完成全部实盘、回测和界面验收。源码默认参数与截图中的个人配置可能不同。金额例子只解释计算方法。

## 1. 产品定位与重要边界

TradeEZ-SOP 是黄金日内交易的半自动执行与风控面板。方向和入场时机由用户选择；EA 负责提交交易、设置初始 SL/TP、管理策略持仓、统计、熔断和数据同步。当前没有自动发现交易信号并自主开仓的逻辑。

使用前必须了解：

- 动态止损、追踪退出、超时平仓和护城河强平依赖 EA 持续执行。同步网络请求及手动同步确认框会暂停本 EA 的事件处理。
- 自动同步的空仓判断针对整个账户；批量平仓及大多数盈亏和风控计算针对当前图表品种。
- 一键全平会处理当前品种的手动单、其他 EA 单和挂单；策略追踪主要按 Magic 识别。
- “改趋势”不改变 Magic、手数或统计归属，仍使用剥头皮追踪规则。
- 异步提交平仓请求不等于已经全部成交，应查看 MT5 交易页确认。
- 手型鼠标功能目前为避免闪烁已停用，默认箭头是当前预期行为。

### 1.1 账户与品种

代码按黄金“1 标准点 = 0.01 价格变化”编写。不能直接将相同参数套用到其他报价体系。账户金额显示使用固定美元符号，但数据取自账户，未实现货币转换。

双策略、逐票管理及趋势部分平仓应在对冲账户（Hedging）上验证。程序没有主动禁止净额账户，但合并持仓会影响策略归属，部分平仓接口也有模式限制。[官方接口说明](https://www.mql5.com/en/docs/standardlibrary/tradeclasses/ctrade/ctradepositionclosepartial)

建议同一账户只运行一个管理实例：当前风控与数组存档没有按图表、品种、Magic 完整隔离，多个实例可能互相覆盖。

### 1.2 单位

| 项目 | 实际定义 |
|---|---|
| 止损、止盈、追踪参数的点 | 1 点 = 0.01 价格变化；300 点 = 3.00 |
| +2空、−2多 | 直接增加/减少 2.00 价格单位 |
| Inp_Slippage | 券商原生报价点，与标准点不同 |
| 盈亏及风控金额 | 账户返回的金额；不保证账户币种是美元 |
| 手数 | 按券商最小量、最大量和步长处理，结果保留两位小数 |

## 2. 安装与首次启用

1. 在 MT5“文件 → 打开数据文件夹”进入 MQL5/Experts/Gold SOP，使用对应目录的 tradeEZ.ex5。
2. 打开实际交易的黄金品种图表，挂载 tradeEZ，避免选择其他目录的同名旧程序。
3. 核对账户模式、品种、两策略 Magic、手数、SL/TP、持仓上限和重置时间。
4. 开启终端算法交易及 EA 交易权限，首次验证使用模拟账户。
5. 官网外部浏览器入口需要“允许 DLL 导入”。这项权限与同步用的 WebRequest 白名单不是同一设置。
6. 使用同步时，开启 Inp_EnableSync，填写可信 API 地址与账户密钥，并在终端 EA 选项中允许该 WebRequest 地址。
7. 检查账户卡片右上角的“同步数据”、标题点击后的两条版本记录，确认加载版本。
8. 有持仓时，核实 MT5 交易页实际 SL/TP。不要仅看按钮颜色判断保护已经生效。

顶栏 v1.03 不随每次修补自动递增，应结合 ex5 编译时间与实际控件判断版本。同步默认关闭；开启后若当天没有每日同步记录，下一次定时事件可能立即补同步，即使有持仓。

灰色按钮主要对应策略熔断或连亏冷却。休市、非交易时段及满仓还会在点击开仓时单独检查，因此亮色不代表一定可成交。

更新日志保留第一版（2026-09-01）和第二版（2026-09-18），以后在源码数据表按新到旧添加，最多显示前 10 条，不会自动下载官网记录。官网按钮打开 https://www.tradeez.cn，需要 DLL 权限。

## 4. 开仓与挂单

### 4.1 市价操作

1. 选择剥头皮或趋势卡片，检查手数和限制。
2. 点击一次“做多”或“做空”。
3. EA 检查券商交易时段、自定北京时间时段、策略禁开状态和当前持仓数量。
4. 剥头皮按参数带 SL/TP；趋势通常只有初始 SL，无固定 TP。
5. 在 MT5 交易页检查成交量、开仓价、SL/TP，不要用按钮反馈代替服务器结果。

开仓快捷入口有 400ms 去抖，网络慢时仍不应反复点击。手数按参数固定，不是自动按亏损金额反推仓位。

### 4.2 限价操作

输入有效价格后点击“限价多”或“限价空”。限价多须低于 Ask，限价空须高于 Bid，均须满足券商最小距离。挂单为 GTC。

| 快捷按钮 | 计算价格 |
|---|---|
| +2空、+3空、+5空 | Bid + 2、3、5 |
| −2多、−3多、−5多 | Ask − 2、3、5 |

持仓上限只统计已存在的策略持仓，不把挂单计入。多笔挂单后续成交可能超出上限。普通熔断不会自动撤销原有挂单。

## 5. 平仓与撤单

| 按钮 | 平仓范围 | 撤挂单 |
|---|---|---|
| 一键全平 | 当前品种全部持仓，含手动及其他 EA | 当前品种全部挂单 |
| 平剥头皮 | 当前品种、剥头皮 Magic | 否 |
| 平趋势单 | 当前品种、趋势 Magic | 否 |
| 平盈利单 | 当前品种 profit + swap > 0，含手动及其他 EA | 否 |

“盈利”过滤不保证扣除全部费用后的净收益为正。四个入口连续异步投递请求，不逐单等成交，但服务器仍分别执行；部分成交、拒绝或重复点击都需要核查。当前没有完整的请求回报对账及残余补平机制。[OrderSendAsync 官方说明](https://www.mql5.com/en/docs/trading/ordersendasync)

平仓后同时检查持仓列表和挂单列表。策略自动追踪平仓仍使用同步交易调用，并未全部改成异步。

## 6. 剥头皮管理

源码默认：0.40 手，最多 1 仓，SL 350 标准点、TP 500 点，追踪触发 300 点，回撤 150 点。图表加载值可以覆盖这些默认值。

### 6.1 SL/TP 与追踪

例如多单参考价 2400.00，默认 SL=2396.50、TP=2405.00；实际以服务器接受结果为准。

达到触发阈值附近（阈值−0.5 点容差）后记录浮盈峰值，保护点数=max(峰值−允许回撤,0)。多单 SL=开仓价+保护点数×0.01，空单相反。SL 只向更有利方向推进，固定 TP 默认保留。

当前限制：每个 Tick 都先判断当前浮盈是否达到启动阈值，跌回阈值以下会提前返回，即便已启动追踪。因此本地峰值回撤平仓并非持续无条件检查；已成功提交的服务器 SL 仍有效。此问题见功能分析报告。

### 6.2 改趋势与撤止盈

“改趋势”要求浮盈达到 Inp_TrendBE1_Trigger。实际撤 TP、保留原 SL，并记录内部标记，不改变 Magic、不立即保本、不改变统计类别，后续仍用剥头皮追踪参数。

“撤止盈”仅处理当前品种已进入剥头皮峰值追踪名单的持仓，保留 SL。没有符合条件持仓时提示；按钮正常样式不保证有可处理持仓。

这两个入口均受 IsScalpAllowed 限制，熔断/冷却时不能通过它们修改持仓。

### 6.3 超时强平

默认关闭。启用后，持仓时间达到 Inp_ScalpMaxHoldSecs，由 Tick 发起平仓；最后最多 30 秒显示倒计时。点击某票号“取消平仓”只取消该仓位超时规则，不取消 SL/TP 或追踪。

无 Tick、网络阻塞或 EA 停止时，不能保证到秒执行。紧凑模式不显示该倒计时侧板，但后台管理仍运行。

## 7. 趋势管理

默认 0.25 手，最多 1 仓，初始 SL 500 点，无固定 TP。

| 浮盈 | 默认动作 |
|---|---|
| ≥300 点 | 尝试把 SL 移到开仓价 |
| ≥500 点 | 尝试锁定 200 点 |
| ≥800 点 | 尝试锁定 500 点，减仓 50% |
| ≥1000 点 | 按当前价格保留 350 点距离推进 SL，记录追踪峰值 |

开仓价保本不包含全部佣金、隔夜费、滑点。减仓量按步长处理，实际比例可能不同；无法拆分的小仓位会被标记为已处理。

追踪分支优先且直接返回：价格跳过减仓档直接达到追踪阈值时，当次可能不减仓；价格跌回追踪阈值以下时也不再在该分支判断峰值回撤。不要把这些行为误认为已实现的连续状态机。

## 8. 风控与护城河

### 8.1 普通亏损额度

默认日额度 500，剥头皮 70%=350，趋势 30%=150。判断使用对应范围已实现+浮动的净盈亏；普通额度不是从峰值计算的回撤，也不是所有亏损成交金额累计。

达到额度禁止新开仓，普通额度熔断本身不全平。净盈亏恢复后可解除，原有挂单仍可能成交。

### 8.2 连亏冷却

当前品种平仓成交（含手动）亏损累加，盈利/保本清零；默认 3 笔后冷却 10 分钟并重置计数。部分平仓也可能参与计数。

Inp_EnableCircuitBreaker=false 并不关闭所有风控：连亏统计在该开关判断前执行，护城河也独立检查。

### 8.3 利润护城河

设 N=当前品种净盈亏（已实现+浮动），H=最高净盈亏。

| 条件 | 当前动作 |
|---|---|
| 未达保护档 | 普通日亏损额度仍适用 |
| H≥第一档 500 | 允许回撤 H×300%（默认确实为 300%，不是 30%） |
| H≥第二档 800 | 允许回撤固定 500，第二档优先 |
| H≥清盘触发 1000 或停止 2000 | 禁止新开仓 |
| 已达保护档且 H−N 达允许回撤 | 异步全平本品种、撤本品种挂单，并锁定当日 |

例：第一档 H=600、比例 300%，计算允许回撤 1800，利润底线 −1200；普通日亏损熔断可能更早触发。参数名称“清盘触发”不意味着刚达到盈利阈值就全部平仓，真正全平由回撤条件触发。

护城河锁定后不会每个 Tick 重新补平失败仓位；弹窗“已平仓”必须用交易页核实。周目标只做统计展示，不自动改参数或平仓。

### 8.4 显示口径

卡片“今日最高盈利”是已实现高水位，护城河内部 H 含浮动，可能不同。动态基准未达档时=初始金额−日额度；第一档=初始金额+H×(1−比例)；第二档=初始金额+H−固定回撤额。

剩余额度显示用整个账户净值减基准，但实际风控主要基于当前品种，多品种交易或入出金会造成显示与真实触发条件不一致。

## 9. 数据同步

### 9.1 内容和权限

同步品种规格、成交记录、账户余额/净值/保证金快照、EA 配置和心跳。成交收集没有限制当前品种或策略 Magic，因此可能上传全账户符合条件的成交。

请求使用 Bearer 密钥和 HMAC-SHA256，时间转为 UTC。使用可信 HTTPS 地址；不要分享含密钥的截图或配置。仅允许 DLL 导入不足以启用 WebRequest，需单独配置白名单。

### 9.2 三种模式

| 模式 | 条件 | 有持仓时 |
|---|---|---|
| 定时自动 | 已启用、有密钥、全账户空仓、没有编辑价格且交互后空闲≥5秒 | 延后 |
| 手动 | 点击同步数据并确认 | 允许 |
| 每日初始化 | 当前统计日尚无已尝试记录 | 允许，不弹手动确认 |

常规定时：成交默认 5 分钟，快照 30 秒，心跳 5 分钟，参数 1 小时，另有初始化品种/参数待办。按已处理定时事件累计，并非严格墙钟周期。一个 SyncDeals 任务可能连续包含多个网络请求。

### 9.3 手动步骤

1. 优先检查全账户空仓以及未成交挂单。
2. 点击账户面板右上角“同步数据”。
3. 阅读确认，默认不继续。确认框等待期间也暂停本 EA，请及时选择。
4. 确认后同步品种、成交、快照、配置和心跳。主面板显示半透明遮罩与“正在同步数据......”。
5. 请求结束，遮罩移除；检查专家日志和复盘系统，不以“同步空闲”代替成功结果。

### 9.4 每日初始化同步

默认北京时间 04:50 划分统计日。定时器发现当前账户+品种的日标记缺失或变化时尝试一次；首次挂载也可能补做，并非一定等到第二天。

标记在请求前保存，表示已尝试，不保证成功。当天重载不重复强制同步。价格编辑中会推迟；持仓不会阻止。不同品种可能分别触发。

### 9.5 增量与失败

先获取服务端游标，首次或获取失败回溯近 7 日。筛选游标后发生平仓成交的 position_id，再向前扩展 30 日收集相关成交。批次成功后才更新游标，失败不推进，重传去重依赖服务端。

现有收集并不严格排除仍有剩余持仓的部分平仓订单，也不能保证超长持仓历史完整。手动及每日同步会上传这类实际收集结果。

### 9.6 阻塞限制

WebRequest 同步等待会暂停本 EA 的 Tick/图表事件处理。已经被券商接受的固定 SL/TP 由服务器执行，但动态追踪会延迟。测试器不能运行 WebRequest，网络能力需在终端验证。[官方说明](https://www.mql5.com/en/docs/network/webrequest)

代码传入 200～800ms 超时，但不能把它当作实测总等待时长保证；此前已观察到更长阻塞，具体阶段未抓包确认。

每个自动请求前重新检查持仓，但未检查挂单。请求过程中挂单成交、其他 EA 或外部终端开仓，均可能在阻塞期间产生新仓位，当前请求不会因此中断。遮罩不锁定整个 MT5，也不锁定其他终端。

## 10. 统计、重置与保存

### 10.1 统计规则

日统计起点为最近配置重置时刻与手动重置时间的较晚者；周起点为北京时间周一 00:00。

笔数按平仓成交，不是完整交易回合；多次减仓可算多笔。多数路径只计 DEAL_ENTRY_OUT，费用主要计平仓成交的 profit+swap+commission，不保证涵盖开仓手续费或独立费用。

日统计采用 ±0.01 附近保本阈值，卡片有按严格正负计算的路径；跨日历史查询范围也不同，胜负或策略归属可能不完全一致。明细最多 30 行，没有分页或显式倒序保证。

### 10.2 重置

每日初始化更新日基线、连亏冷却、高水位及锁定状态，不是平仓/撤单指令。手动重置立即重新设统计起点和余额基准并清除相关限制，不二次确认，不自动完整同步，也不手动导出报告。现有浮亏仍可能使下一次检查重新熔断。

### 10.3 文件与状态

| 内容 | 位置/名称 |
|---|---|
| 日报告 | 数据目录/MQL5/Files/TradeEZ_账户_日期.md |
| 追踪、减仓及取消超时状态 | MQL5/Files/GSOP_state_账户.csv |
| 风控状态 | 终端全局变量 GSOP_账户_… |
| 每日同步标记 | TEZ.SyncDay.账户.品种 |

日报告在允许导出的跨日流程中尝试生成，当前存在跨日选区问题，可能不能准确反映刚结束的一天；正式使用须核对日期和明细。部分状态只恢复本统计日有效存档，多实例和跨日重载有边界，详见分析报告。

## 11. 日常操作流程

### 开始前

1. 确认账户、黄金品种、对冲模式和唯一管理实例。
2. 检查交易权限、报价、当前实际持仓及挂单。
3. 确认所有预期 SL/TP 在服务器持仓字段中存在。
4. 核对手数、额度、护城河比例和每日重置时间。
5. 判断是否允许补做当日同步；不能接受动态风控暂停时先关闭同步。

### 交易中

1. 自行确定策略与方向，单次点击后核对成交。
2. 查看 SL 推进和减仓是否真实完成。
3. 熔断时先检查原因，不把重置当作常规绕过风控的入口。
4. 全平后复查残余持仓与挂单。

### 结束后

1. 确认仓位、挂单符合计划。
2. 空仓时同步，并核对专家日志、复盘系统。
3. 对比 MT5 历史和日统计的费用、分批成交及统计日。
4. 保存配置与报告，保留异常日志；升级前记录已有持仓管理状态。

## 12. 常见问题

| 问题 | 核查方向 |
|---|---|
| 亮色按钮却不能开仓 | 休市、时段、持仓上限、交易权限、服务器拒绝码 |
| 限价失败 | 输入价格、方向、最小距离和券商 SL/TP 要求 |
| 改趋势后仍归剥头皮 | 当前实现不修改 Magic，属预期 |
| 撤止盈无效 | 未进入追踪、无 TP、入口受限或请求未成功 |
| 自动同步不启动 | 全账户持仓、持续鼠标活动、编辑中、开关、密钥 |
| 有仓仍同步 | 手动/每日例外，或请求发起后产生仓位 |
| 空闲但复盘没数据 | 空闲不是成功，检查接口和游标结果 |
| 全平后仍有单 | 提交失败、部分成交、挂单竞态、多实例；核查交易页 |
| 统计不同 | 品种范围、日基线、成交计数、跨日归属和费用 |
| 没有手型 | 当前已停用 |
| 官网打不开 | DLL 权限、默认浏览器；可手动访问官网 |
| 更新后仍旧 | 同名旧程序、目录错误或未重载 |
