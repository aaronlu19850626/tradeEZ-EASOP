# TradeEZ 官网 UI 选型与设计提示词

调研日期：2026-09-18  
本次交付：开源方案比较、推荐方向及可复用提示词；不安装依赖、不开发或发布网站。

## 1. 推荐结论

推荐使用 **shadcn/ui 作为交互组件基础，配合自定义样式完成官网**。官网的品牌表现由排版、内容组织、产品截图及一致的视觉规范决定，不直接继承某个 Landing Page 模板。

shadcn/ui 更准确地说是可复制、修改的组件代码体系，不是包办网站设计的整站框架。它适合作为菜单、按钮、标签页、折叠面板等基础。首屏、产品展示和工作流程需要针对 TradeEZ 独立设计。

若优先追求统一、克制且较少自行定义的控件外观，可选 Radix Themes。两者选一套作为主要基础，不叠加多个完整组件库。

## 2. GitHub 候选

以下项目事实来自官方仓库及文档；适合程度属于针对本项目的设计判断，不是客观排名。未对每个项目做本地安装、性能或兼容性测试。

| 项目 | 开源与定位 | TradeEZ 使用建议 |
|---|---|---|
| [shadcn/ui](https://github.com/shadcn-ui/ui) | MIT；可组合、可自定义的组件代码；官方提供文档和持续发布记录 | 首选。控件按需采用，官网布局和主题自己设计 |
| [Radix Themes](https://github.com/radix-ui/themes) | MIT；由 WorkOS 维护，强调一致性、可维护性和可访问性 | 备选。适合克制统一的产品界面；官网仍需要专门布局 |
| [HeroUI](https://github.com/heroui-inc/heroui) | React UI 库；当前 v3 仓库许可证为 Apache-2.0 | 可选。适合较完整的交互界面，需重设主题以匹配品牌 |
| [Magic UI](https://github.com/magicuidesign/magicui) | 官方定位为可复制的动画组件和视觉效果库 | 仅考虑局部效果，不作为整站审美来源；使用具体代码前核对其许可证 |

维护情况：已查看 shadcn/ui 官方发布页及 Radix Themes 提交历史，存在持续更新记录。HeroUI 当前仓库使用 v3 分支，实施时必须按选定版本的文档和依赖要求进行核对。这里不以星标数量证明质量，也不承诺未来维护状态。

许可证适用于对应仓库代码，不自动覆盖第三方模板、付费组件包、字体、截图及图标等附加资产。商业使用时保留项目要求的许可声明。

## 3. 推荐视觉方向

**深蓝灰产品官网，清楚、克制、有真实交易工具的辨识度。**

继承 EA 的蓝灰与金色线索，但增加留白和字号层级，让官网适合阅读。重点表现“执行—记录—复盘”的关系，避免把交易界面的密集程度搬到官网。

色彩建议是本项目初稿，需要实际检验对比度：

| 用途 | 色值 |
|---|---|
| 主背景 | #0D1015 |
| 产品展示底面 | #151A23 |
| 控件／次级面 | #1D222C |
| 分隔线 | #303A49 |
| 标题 | #F0F3F6 |
| 正文 | #B0BAC9 |
| 次级说明 | #98A6B8 |
| 主操作 | #356FE6 |
| 主操作文字 | #FFFFFF |
| 品牌点缀 | #C3A66A |

金色用于细小标记、章节编号或单条强调线；蓝色用于链接和主要行动；交易盈亏颜色只出现在有语义的数据画面中。不要把红绿涨跌色变成全站品牌主色。

建议的参考站点是 [Linear](https://linear.app/)、[Stripe](https://stripe.com/) 和 [Vercel](https://vercel.com/)。它们只作为产品叙事和阅读组织的参考对象，分别观察真实产品内容如何进入页面、多产品如何解释、导航如何分层。这里不声称复制其当前视觉，也不把它们当成可直接复用的开源模板。

## 4. 主提示词：官网设计与后续实现

以下内容可以完整复制。执行端没有本地文件访问权限时，应同时提供相关文案文件内容。

```text
你是一名擅长中文金融工具与专业软件官网的资深产品设计师，同时能够将设计落实为可靠的响应式前端。

为 TradeEZ 设计官网。先读取提供的官网文案和产品状态，不自行编造功能、用户量、合作品牌、收益、评价、价格或上线时间。

一、产品事实
TradeEZ 包括两部分：
1. MT5 EA：交易执行辅助、剥头皮与趋势持仓管理、风险限制、统计和周期数据同步。
2. Web SaaS：首版筹备中，围绕交易日志、标签、规则评价、分析、盘前计划、盘后复盘及改进行动。
AI 复盘、课程案例、回放练习和进阶研究属于未来规划。

品牌主张：让每一笔交易有计划、有纪律、有复盘。
官网文案来源：website-design/01-website-copy-v1.md。
产品需求来源：tradeEZ-docs/tradeEZ-docs/16-phase1-functional-requirements.md。

二、设计目标
访客首先看懂产品是什么，然后理解 EA 和平台如何配合，最后找到适合当前产品状态的下一步。
视觉应稳重、清楚、精细，具有专业软件官网的完成度。
不要仅通过加入炫光和动效表达“先进”。设计必须在静态截图中也成立。

三、组件选择
使用 shadcn/ui 作为必要交互组件的基础；按需使用按钮、导航、标签页、折叠面板和对话框。
不直接堆叠预制 Landing Page 区块。首屏与产品展示独立设计。
如项目已有技术栈，优先兼容现有环境，不为套用组件擅自更换整个项目。
实施前检查当前稳定文档和依赖兼容性，不猜测版本或复制过时安装命令。

四、视觉规范
深蓝灰背景 #0D1015；展示面 #151A23；控件面 #1D222C。
标题 #F0F3F6；正文 #B0BAC9；次级文本 #98A6B8。
主要操作采用 #356FE6，少量 #C3A66A 作为金色品牌点缀。
完成设计后实际检测文字、按钮、边界和焦点的可辨识度，必要时调整色值。
按钮和控件圆角 6–8px，产品画面容器 10–12px，少量状态标签可用胶囊形。
阴影仅帮助区分层次，避免发光阴影和层层嵌套面板。

五、中文排版
中文优先使用系统无衬线字体，英文及数字使用相协调的无衬线字体。
字体回退可采用 system-ui、PingFang SC、Microsoft YaHei、sans-serif。
不要要求依赖境外字体服务才能正常显示，也不要为整页加载过重的完整中文字体。
桌面正文 16–18px，行高约 1.7；中文说明段落每行约 28–38 字。
桌面主标题从 48–64px 范围内按实际内容调整，移动端约 32–40px。
控制主标题断行，避免单字孤行，避免用英文字母式负字距处理中文。
正文依靠层级、段落与留白组织，不把所有句子加粗。

六、版式
桌面内容宽度约 1200px，主要使用一致的 12 列对齐关系。
桌面章节垂直间距约 88–120px，移动端约 48–64px，具体按内容调整。
首屏采用文字与产品画面并列的非对称布局。真实截图保持原比例，必要时用局部放大解释，不能拉伸或倾斜到无法阅读。
如果画面素材尚未提供，显示精心排版的占位面，名称、图注和替换位置明确。
首页以价值摘要引导到产品页，不能把全部长文机械塞入一页。
产品页保留充分细节，使用正文、功能列表、参数关系、流程示意、对比表和截图注释。
相邻章节要有不同阅读节奏，不连续使用相同的三列卡片布局。

七、首页结构
1. 简洁导航：产品、EA、平台、使用流程、规划、帮助。
2. 首屏：价值主张、两段以内说明、两个有真实落点的按钮、产品画面。
3. 交易者的问题：具体描述记录、执行和复盘的断点。
4. 产品分工：EA 执行管理、平台计划分析；说明数据连接。
5. EA 深入展示：真实面板或占位，配双策略、持仓管理和风险状态说明。
6. 平台深入展示：交易事实、规则检查、复盘行动，明确“首版设计预览”。
7. 一个交易日：从准备、执行到复盘，采用顺序清楚的流程。
8. 执行理念：遵守规则但亏损、违规却盈利、条件未到而不交易。
9. 未来路线：紧凑、清楚，所有能力标注规划状态。
10. FAQ、合适的下一步和页脚。

八、产品展示
图片优先使用真实、脱敏的 EA 截图。
SaaS 原型明确标注设计预览；模拟交易数据标注示意数据。
占位内容应帮助理解功能，例如成交时间线、规则清单、每日流程结构；不要只放一个巨大空灰框。
原型表格中的任何示意数据不作为业绩背书，不展示虚构增长数字或胜率成就。
图标只在提高理解或操作识别时使用，统一线宽，不给每段文字强行配图标。

九、交互与响应式
导航、标签页和 FAQ 必须可用键盘操作，焦点清晰。
动效使用短暂的淡入或小幅位移，通常约 160–240ms。
内容默认可见；关闭脚本或开启减少动画偏好后，不应出现大块空白。
不劫持滚动，不自动播放大视频，不让关键文字依赖悬停出现。
移动端重排内容，不能把整个桌面缩小。截图细节可提供放大查看入口。
检查 390px、768px、1440px 视口；正文不横向溢出，长链接不撑破布局。
触控目标以至少约 44px 为设计目标。

十、避免以下模板特征
紫蓝渐变光团、大面积毛玻璃、星空粒子、霓虹网格、漂浮金币、装饰性上涨 K 线。
所有章节都是居中大标题加三张等宽卡片。
所有元素都放进大圆角盒子，所有按钮都使用发光描边。
首屏完全被空泛口号占满，实际产品缩成不可读的小图。
重复写“颠覆、赋能、下一代、革命性”等无具体含义的词。
为了商业感添加虚构用户头像、合作 logo、倒计时、订阅价格和收益承诺。
将后台工作台的左侧菜单直接用作官网导航。

十一、输出要求
先输出页面结构和统一的视觉规范，再按这套规范产出设计或代码。
完成首页与 EA、平台、规划、FAQ 的内容分配；同一概念命名一致。
所有按钮有真实页面、页内锚点或可解释的状态；未开放功能不得显示假注册成功。
说明图片替换位置、当前模拟内容与尚需提供的资料。
交付前按桌面和移动端检查内容、布局、键盘操作与状态标签。
最后从识别度、可读性、内容层次、响应式和真实产品表达五个方面进行自查，修改具体问题，不只给出“高级、现代”的自我评价。
```

## 5. 第二轮提示词：去除模板感

```text
审查当前 TradeEZ 官网设计，目标是减少重复模板结构，增强专业产品的真实感。

请逐屏检查：
1. 是否能在首屏判断它是 MT5 EA 与交易复盘平台？若不能，调整产品画面与文字优先级。
2. 连续三个章节是否采用相同卡片结构？若是，按信息内容改成图文对照、流程、表格或带注释的产品画面。
3. 是否有只装饰、不传达信息的光效、图标、背景图和数字？逐项删除或换成有依据的产品内容。
4. 深色页面是否有足够的文字对比和段落层次？检查次级文字，不靠极低透明度制造层次。
5. 中文标题断行、段落宽度、字体粗细是否经过人工式调整？修复孤行和过长行。
6. 内容是否从正文文件机械复制，造成首页过长？保留首页摘要和进入产品详情的路径，不删除重要产品说明。
7. EA、SaaS 首版和未来规划是否准确区分？修改可能产生误解的下载、注册和体验入口。
8. 删除品牌名后是否仍然像任何一个普通 SaaS 模板？增加 TradeEZ 特有的双策略画面、规则评价和每日流程内容。

请输出具体发现与修改，并保留已做好的排版与功能。不要通过增加动画、渐变和阴影解决这些问题。
```

## 6. 第三轮提示词：上线前检查

```text
对 TradeEZ 官网页面进行发布前审查。
核对文案与产品需求的一致性；核对所有按钮、链接和图片状态。
检查移动端溢出、菜单开关、FAQ 键盘操作、焦点状态、减少动画偏好和图片加载时的布局稳定性。
检查当前能力、筹备中的平台和未来功能标识是否可见。
清理开发说明、图片任务编号、调试信息和没有解释的占位文字。
真实截图脱敏；原型标注设计预览；演示数据标注示意数据。
没有真实后端的表单不显示成功提交；没有真实下载文件的按钮不伪装下载完成。
逐项报告实际验证结果与未验证项，不把视觉完成当成功能已上线。
```

## 7. 设计验收标准

- 首屏清楚表达产品及其组合关系。
- 主要产品画面有可读细节，比例真实。
- 复杂文案被合理分配到产品页，首页阅读有节奏。
- 有统一的字体、色彩、对齐、圆角和间距规则。
- 深色主题下说明文字清晰，不依赖装饰特效。
- “真实可用、设计预览、未来规划”状态准确。
- 键盘与触控操作成立；减少动画后内容仍完整。
- 不含虚构业绩、品牌背书或上线承诺。

这是设计方向和可执行提示词，不代表已构建或验证最终页面。
